    bhyve(display): add shell integration test for console multi-instance + legacy (T8.D)
    
    Adds tests/sys/vmm/console_multi_instance.sh with four ATF shell cases that
    
    exercise the per-instance console API introduced in T8.A:
    
      1. sh_console_bhyve_singleton_unchanged
    
         Build bhyve (or fall back to the installed binary) and verify the
    
         legacy -h smoke path still works.
    
      2. sh_console_two_jails_concurrent  [expected_failure]
    
         Spawn two jails with allow.fbuf=1; fails until T0.D + T9 land.
    
      3. sh_console_jail_and_bhyve_concurrent  [expected_failure]
    
         Run a jail and bhyve concurrently sharing the console subsystem.
    
      4. sh_console_destroyed_jail_console_freed  [expected_failure]
    
         Start, kill, restart a jail with the same name; allow.fbuf=1
    
         must be accepted on the second creation.
    
    Cases 2-4 use atf_expect_fail + atf_check -s exit:0 so the red state
    
    (jail: unknown parameter: allow.fbuf) is recorded as a passing
    
    expected failure. When T0.D + T9 land, jail succeeds, atf_check passes,
    
    and the expected_failure flips to a real failure that is re-baselined.
    
    test_suite/Kyuafile plumbing:
    
      - tests/sys/vmm/Makefile: append console_multi_instance to ATF_TESTS_SH.
    
      - tests/sys/vmm/Kyuafile:  new (auto-generated by bmake) registering
    
        both vmm_cred_jail and console_multi_instance with kyua.
    
    Verified: sh -n exit 0; kyua reports 4/4 passed (1 real + 3 expected_failure).
