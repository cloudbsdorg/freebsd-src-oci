## 18.1 Executive Summary

This document defines tooling for exporting FreeBSD containers to common cloud providers (AWS, GCP, Azure) and migrating containers between environments. Since OCI containers are implemented as FreeBSD jails, the export tooling must handle both traditional containers and live jails, preserving volume data and adapting network configurations for each target environment.

**Key Capabilities:**
- **Flat Export** — Convert any container or jail to a portable, cloud-ready image format
- **Live Export** — Export running containers with their current state and volume data
- **Jail to Container** — Convert existing FreeBSD jails to standard OCI containers
- **Cloud Upload** — Direct upload to AWS (AMI), GCP (GCE), Azure (VHD)
- **Network Adaptation** — Automatically adjust network configurations for target environment

**What This Document Covers:**
| Area | Problem | Our Approach |
|------|---------|-------------|
| Container export | No standard way to export FreeBSD containers | Flat tar/cert format with metadata |
| Running container export | Need to export live state with volumes | Freeze + snapshot + stream |
| Jail to container | Existing jails aren't OCI-compatible | Conversion layer with manifest generation |
| Cloud upload | Manual upload process is error-prone | Integrated upload commands |
| Network adaptation | Networks differ between environments | Environment detection + auto-config |

## 18.2 Export Architecture

### 18.2.1 Flat Export Format

The flat export format is designed for portability across all cloud providers:

```
┌─────────────────────────────────────────────────────────────┐
│                    Flat Export Bundle (.feb)                │
├─────────────────────────────────────────────────────────────┤
│ manifest.json           # Export metadata and instructions   │
│ rootfs.tar.gz           # Filesystem snapshot               │
│ volumes/                # Volume snapshots                   │
│   ├── volume-1.zfs.gz  # ZFS snapshot of volume-1           │
│   └── volume-2.zfs.gz  # ZFS snapshot of volume-2           │
│ config.json             # Container/jail configuration       │
│ network.json            # Network configuration             │
│ certs/                  # Certificates (if bundled)          │
│ metadata.json           # Creation timestamp, version       │
└─────────────────────────────────────────────────────────────┘
```

**manifest.json Structure:**
```json
{
  "version": "1.0",
  "created": "2026-04-30T10:00:00Z",
  "source": {
    "type": "container",  // or "jail"
    "name": "myapp-prod",
    "id": "abc123",
    "hostname": "myapp"
  },
  "target": {
    "provider": "aws",  // aws, gcp, azure, generic
    "format": "ami"     // ami, gce-tar, vhd, raw
  },
  "volumes": [
    {
      "name": "data",
      "source": "/data",
      "snapshot": "volume-1.zfs.gz"
    }
  ],
  "network": {
    "mode": "bridge",
    "interfaces": [
      {
        "name": "eth0",
        "type": "ethernet",
        "mac": "02:03:04:05:06:07"
      }
    ]
  },
  "entrypoint": ["/bin/sh", "-c", "/start.sh"],
  "environment": {
    "DATABASE_URL": "${DATABASE_URL}",
    "API_KEY": "${API_KEY}"
  }
}
```

### 18.2.2 Container to Export

Converting a stopped container to an export bundle:

```bash
# Export a stopped container
ocifbsd export myapp --output myapp.feb

# Export with volumes included
ocifbsd export myapp --output myapp.feb --include-volumes

# Export to specific cloud format
ocifbsd export myapp --output myapp.tar.gz --format aws

# Export with compression
ocifbsd export myapp --output myapp.feb --compress zstd
```

**Export Process:**
```
ocifbsd export myapp
    │
    ▼
Check: container is stopped
    │
    ▼
Create temporary snapshot (if running)
    │
    ▼
Dump rootfs to rootfs.tar.gz
    │
    ▼
Export volumes to volumes/*.zfs.gz
    │
    ▼
Generate manifest.json
    │
    ▼
Generate config.json (OCI-compliant)
    │
    ▼
Package everything into .feb bundle
    │
    ▼
Clean up temporary snapshots
```

### 18.2.3 Jail to Container Conversion

Converting an existing FreeBSD jail to a standard OCI container:

```bash
# Convert a jail to OCI container format
ocifbsd jail-to-container myjail --output mycontainer/

# Convert and import into container runtime
ocifbsd jail-to-container myjail --import

# Convert with all jail parameters preserved
ocifbsd jail-to-container myjail --preserve-all --output mycontainer/
```

**Jail Parameters Mapped to OCI:**
| Jail Parameter | OCI Equivalent | Notes |
|---------------|----------------|-------|
| `name` | `hostname` | Container hostname |
| `host.hostname` | `hostname` in config.json | |
| `security.jail.user` | N/A | Linux-specific |
| `devfs_ruleset` | `linux.devices` | Device access |
| `children.max` | `linux.cgroups.max` | Process limits |
| `enforce_statfs` | N/A | FreeBSD-specific |
| `exec.prestart` | `prestart` hook | |
| `exec.poststop` | `poststop` hook | |
| `ip4.addr` | `network.interfaces` | Port mapping |
| `ip6.addr` | `network.interfaces` | IPv6 support |
| `vnet` | `network.mode: bridge` | Network namespace |
| `allow.raw_sockets` | `linux.capabilities` | Raw socket access |
| `rlimits` | `linux.resources` | Resource limits |
| `persist` | `process.pidfile` | Persistent jail |
| `path` | `rootfs` | Filesystem root |

### 18.2.4 Running Container Export with Volumes

Exporting a running container requires coordination to ensure data consistency:

```bash
# Export running container (with brief pause for consistency)
ocifbsd export --running myapp --output myapp-live.feb

# Export with volume snapshots
ocifbsd export --running myapp --output myapp-live.feb --snapshot-volumes

# Export with minimal downtime (< 1 second)
ocifbsd export --running myapp --output myapp-live.feb --quick-freeze
```

**Live Export Process:**
```
ocifbsd export --running myapp
    │
    ▼
Signal application: prepare for snapshot (SIGUSR1)
    │
    ▼
Application acknowledges (or timeout after 30s)
    │
    ▼
Pause container (freeze jail)
    │
    ▼
Create ZFS snapshots of all volumes
    │
    ▼
Dump rootfs to rootfs.tar.gz
    │
    ▼
Export volume snapshots
    │
    ▼
Resume container (thaw jail)
    │
    ▼
Package everything into .feb bundle
    │
    ▼
Clean up ZFS snapshots (optional: retain for recovery)
```

**Application Coordination:**
Containers can opt-in to snapshot coordination via a Unix socket:

```bash
# Container signals ready for snapshot
echo "SNAPSHOT_READY" | nc -U /var/run/ocifbsd/coordination.sock

# Or via environment variable
export OCIFBSD_COORDINATION_SOCKET=/var/run/ocifbsd/coordination.sock
```

## 18.3 Cloud Provider Support

### 18.3.1 AWS Export

**Target Format:** Amazon Machine Image (AMI)

**Requirements:**
- AWS CLI configured with appropriate credentials
- Target region specified
- S3 bucket for intermediate storage (optional)
- IAM permissions for AMI creation

```bash
# Export to AWS AMI
ocifbsd cloud export aws --container myapp --region us-east-1 --ami-name myapp-$(date +%Y%m%d)

# Export with custom instance type
ocifbsd cloud export aws --container myapp --instance-type t3.medium

# Export with encryption
ocifbsd cloud export aws --container myapp --encrypted --kms-key alias/my-key

# Export with networking
ocifbsd cloud export aws --container myapp --vpc vpc-12345 --subnet subnet-67890
```

**AWS-Specific Configuration:**
```yaml
# /etc/ocifbsd/cloud/aws.yaml
aws:
  region: us-east-1
  s3_bucket: ocifbsd-exports
  ami:
    name_prefix: ocifbsd-
    description: "OCI Container exported from FreeBSD"
    virtualization: hvm
    root_device: /dev/xvda
    volume_type: gp3
    
  networking:
    vpc: auto              # auto-detect or specify VPC ID
    subnet: auto
    security_groups:
      - sg-12345678        # or "default"
    assign_public_ip: true
    
  permissions:
    snapshot: true
    share_with_accounts:
      - "123456789012"
```

**AWS Export Process:**
```
Container Export
    │
    ▼
Convert to raw disk image
    │
    ▼
Upload to S3 bucket
    │
    ▼
Import as EBS snapshot
    │
    ▼
Create AMI from snapshot
    │
    ▼
Clean up S3 objects
```

### 18.3.2 GCP Export

**Target Format:** GCE-compatible tar.gz with disk image

**Requirements:**
- Google Cloud SDK configured
- Project ID specified
- GCS bucket for intermediate storage
- Appropriate IAM roles

```bash
# Export to GCP
ocifbsd cloud export gcp --container myapp --project my-project --zone us-central1-a

# Export with custom machine type
ocifbsd cloud export gcp --container myapp --machine-type n2-standard-2

# Export with networking
ocifbsd cloud export gcp --container myapp --network my-vpc --subnet my-subnet

# Export with encryption
ocifbsd cloud export gcp --container myapp --kms-key projects/my-project/locations/global/keyRings/my-ring/cryptoKeys/my-key
```

**GCP-Specific Configuration:**
```yaml
# /etc/ocifbsd/cloud/gcp.yaml
gcp:
  project: my-project
  zone: us-central1-a
  storage:
    bucket: ocifbsd-exports
    prefix: containers/
    
  compute:
    machine_type: n2-standard-2
    image_family: ocifbsd
    image_description: "OCI Container exported from FreeBSD"
    disk_size_gb: 20
    disk_type: pd-ssd
    
  networking:
    network: auto
    subnetwork: auto
    external_ip: ephemeral
    firewall_rules:
      - name: allow-ssh
        allowed: [tcp:22]
      - name: allow-https
        allowed: [tcp:443]
        
  security:
    kms_key: null           # Optional CMEK
    service_account: auto    # Use default or specify
```

**GCP Export Process:**
```
Container Export
    │
    ▼
Convert to raw disk image
    │
    ▼
Create tar.gz with disk image + manifest
    │
    ▼
Upload to GCS bucket
    │
    ▼
Import as GCE image
    │
    ▼
Clean up GCS objects
```

### 18.3.3 Azure Export

**Target Format:** Virtual Hard Disk (VHD)

**Requirements:**
- Azure CLI configured
- Resource group and storage account specified
- Appropriate IAM roles

```bash
# Export to Azure
ocifbsd cloud export azure --container myapp --resource-group my-rg --location eastus

# Export with custom VM size
ocifbsd cloud export azure --container myapp --vm-size Standard_D2s_v3

# Export with networking
ocifbsd cloud export azure --container myapp --vnet my-vnet --subnet my-subnet

# Export with encryption
ocifbsd cloud export azure --container myapp --encryption-type EncryptionAtHost
```

**Azure-Specific Configuration:**
```yaml
# /etc/ocifbsd/cloud/azure.yaml
azure:
  subscription: my-subscription-id
  resource_group: my-resource-group
  location: eastus
  storage:
    account: ocifbsdexports
    container: vhds
    sku: Standard_LRS           # or Premium_LRS, StandardSSD_LRS
    
  compute:
    vm_size: Standard_D2s_v3
    offer: FreeBSD
    sku: "14"
    version: "latest"
    
  networking:
    virtual_network: auto
    subnet: auto
    security_group: auto
    public_ip: true
    
  security:
    encryption_at_host: false
    disk_encryption_set: null   # Optional DES resource ID
```

**Azure Export Process:**
```
Container Export
    │
    ▼
Convert to VHD format (fixed size, page-aligned)
    │
    ▼
Upload to Azure Storage
    │
    ▼
Create managed disk from VHD
    │
    ▼
Create VM image from managed disk
    │
    ▼
Clean up storage
```

### 18.3.4 Other Cloud Providers

**Generic Export:**
```bash
# Export to generic format (tar.gz)
ocifbsd cloud export generic --container myapp --output myapp.tar.gz

# Export to Docker/OCI image
ocifbsd cloud export oci --container myapp --output myapp.tar

# Export to QCOW2 (for KVM/QEMU)
ocifbsd cloud export qcow2 --container myapp --output myapp.qcow2

# Export to VMDK (for VMware)
ocifbsd cloud export vmdk --container myapp --output myapp.vmdk
```

**Supported Formats:**
| Format | Provider | Use Case |
|--------|----------|----------|
| `.feb` | FreeBSD native | Our portable format |
| `.tar.gz` | Generic | Manual upload |
| `ami` | AWS | Amazon EC2 |
| `gce-tar.gz` | GCP | Google Compute Engine |
| `.vhd` | Azure | Azure Virtual Machines |
| `.qcow2` | KVM/QEMU | Local virtualization |
| `.vmdk` | VMware | VMware vSphere/Workstation |
| `.vdi` | VirtualBox | VirtualBox |
| `.raw` | Generic | dd/cat to device |

## 18.4 Network Interface Adaptation

Different cloud environments have different network configurations. Our export tooling detects and adapts to these differences.

### 18.4.1 Network Environment Detection

The export process analyzes the source environment and adapts to the target:

```bash
# Show detected network environment
ocifbsd network detect

# Output:
# Hostname: myapp
# Interfaces:
#   - lo0: loopback (127.0.0.1)
#   - epair0a: bridge to host (10.0.0.5/24)
#   - epair0b: container interface (172.20.0.5/16)
# DNS: 10.0.0.1, 8.8.8.8
# Gateway: 10.0.0.1
# Routes:
#   - default via 10.0.0.1
#   - 172.20.0.0/16 via epair0b
```

**Detection Heuristics:**
| Pattern | Environment | Adaptation |
|---------|-------------|------------|
| `vtnet0`, ` enx*` | AWS EC2 | Use EC2 networking |
| `eth0` | GCP GCE | Use GCE networking |
| `eth0`, Azure MAC prefix | Azure | Use Azure networking |
| `em0`, `igb0` | Bare metal | Use standard DHCP |
| No network config | Unknown | Use conservative defaults |

### 18.4.2 Auto-Configuration Profiles

Each cloud provider has a network profile:

```yaml
# /etc/ocifbsd/cloud/network-profiles.yaml
network_profiles:
  aws:
    interface_name: eth0
    mac_prefix: "02:"
    dhcp: true
    dns_servers:
      - "169.254.169.253"   # AWS DNS
      - "8.8.8.8"
    hostname_source: dhcp    # or "metadata"
    metadata_service: "http://169.254.169.254/latest/meta-data/"
    
  gcp:
    interface_name: eth0
    mac_prefix: "42:"
    dhcp: true
    dns_servers:
      - "169.254.169.254"   # GCP DNS
    hostname_source: metadata
    metadata_service: "http://metadata.google.internal/computeMetadata/v1/"
    
  azure:
    interface_name: eth0
    mac_prefix: "00:0d:3a:" # Azure MAC prefix
    dhcp: true
    dns_servers:
      - "168.63.129.16"     # Azure DNS
    hostname_source: dhcp
    metadata_service: "http://169.254.169.254/metadata/instance"
    
  on_prem:
    interface_name: em0
    mac_prefix: null       # Any
    dhcp: true
    dns_servers:
      - "8.8.8.8"
      - "8.8.4.4"
    hostname_source: static
```

### 18.4.3 Network Translation Rules

Automatic translation of FreeBSD network config to target environment:

| FreeBSD Config | AWS Translation | GCP Translation | Azure Translation |
|---------------|-----------------|-----------------|-------------------|
| `epair0a` | `eth0` | `eth0` | `eth0` |
| `vlan` | Secondary ENI | Secondary NIC | Secondary NIC |
| `bridge0` | Default VPC switch | Default network | VNet |
| Static IP | Keep (recommend DHCP) | Keep (recommend DHCP) | Keep (recommend DHCP) |
| `pf` rules | Security Groups | Firewall rules | NSG rules |
| `/etc/resolv.conf` | Auto (DHCP) | Auto (DHCP) | Auto (DHCP) |
| `hostname` | Auto (DHCP) | From metadata | Auto (DHCP) |

**Translation Example:**
```bash
# Original jail network config
network:
  interfaces:
    - name: epair0a
      type: ether
      addresses:
        - 10.0.0.5/24
      gateway: 10.0.0.1
  dns:
    servers: [10.0.0.1, 8.8.8.8]
    search: [internal.example.com]
```

**Translates to AWS:**
```json
{
  "interfaces": [
    {
      "name": "eth0",
      "type": "ether",
      "dhcp": true,
      "secondary_addresses": [
        {
          "address": "10.0.0.5",
          "netmask": 24
        }
      ]
    }
  ],
  "dns": {
    "servers": ["169.254.169.253", "8.8.8.8"],
    "search": ["internal.example.com"]
  }
}
```

## 18.5 CLI Commands

```bash
# Export commands
ocifbsd export <container> --output <file>           # Export container
ocifbsd export --running <container>                 # Export running container
ocifbsd export --include-volumes                     # Include volume data
ocifbsd export --format <format>                     # Specify format (aws, gcp, azure, generic)
ocifbsd export --compress <algorithm>                # Compression (zstd, gzip, none)

# Jail to container conversion
ocifbsd jail-to-container <jail> --output <dir>     # Convert jail to container
ocifbsd jail-to-container <jail> --import            # Convert and import

# Cloud export commands
ocifbsd cloud export aws <container>                 # Export to AWS AMI
ocifbsd cloud export gcp <container>                 # Export to GCP
ocifbsd cloud export azure <container>                # Export to Azure
ocifbsd cloud export generic <container>              # Export to generic format
ocifbsd cloud export oci <container>                  # Export as OCI image

# Cloud import commands
ocifbsd cloud import aws --ami <ami-id>              # Import from AWS AMI
ocifbsd cloud import gcp --image <image-name>        # Import from GCP
ocifbsd cloud import azure --image <image-name>       # Import from Azure
ocifbsd cloud import file <file>                      # Import from file

# Network commands
ocifbsd network detect                                # Detect network environment
ocifbsd network profiles list                          # List available profiles
ocifbsd network translate <export-file> --target aws # Translate for target

# Volume commands
ocifbsd volume snapshot <volume> --output <file>    # Snapshot volume
ocifbsd volume restore <snapshot> --to <volume>       # Restore from snapshot
ocifbsd volume export <volume> --output <file>       # Export volume
ocifbsd volume import <file> --name <volume>          # Import volume

# Bundle commands
ocifbsd bundle create <container> --output <file>    # Create export bundle
ocifbsd bundle extract <bundle> --to <dir>           # Extract bundle
ocifbsd bundle info <bundle>                          # Show bundle info
```

## 18.6 Configuration

```yaml
# /etc/ocifbsd/export.yaml
export:
  # Default export settings
  defaults:
    format: feb              # feb, tar.gz, aws, gcp, azure
    compression: zstd        # zstd, gzip, none
    include_volumes: true
    include_secrets: false   # Never export secrets by default
    
  # Flat export settings
  flat:
    manifest_version: "1.0"
    rootfs_format: tar.gz
    volume_format: zfs-send  # or tar.gz
    metadata_include:
      - created
      - source_type
      - source_name
      - target_provider
      
  # Running container export
  live_export:
    freeze_timeout: 30s
    snapshot_method: zfs-freeze
    coord_socket: /var/run/ocifbsd/coordination.sock
    preserve_snapshots: false
    
  # Jail conversion
  jail_conversion:
    preserve_jail_params: true
    generate_oci_manifest: true
    warn_on_unsupported: true
    
# /etc/ocifbsd/cloud.yaml
cloud:
  # AWS settings
  aws:
    region: auto             # Or specify region
    s3_bucket: null         # Auto-created if null
    ami:
      name_prefix: ocifbsd-
      description: "OCI Container from FreeBSD"
      
  # GCP settings
  gcp:
    project: null           # Must be specified
    zone: auto
    storage_bucket: null    # Auto-created if null
    
  # Azure settings
  azure:
    resource_group: null    # Must be specified
    location: auto
    storage_account: null   # Auto-created if null
    
  # Network adaptation
  network:
    auto_detect: true
    default_profile: aws    # Used if detection fails
    translation:
      interface_names:
        epair: eth          # epair0a -> eth0
        lo: lo              # lo0 -> lo
      address_preservation: prefer-dhcp  # prefer-dhcp, preserve, translate
        
  # Upload credentials
  credentials:
    aws_profile: default
    gcp_application_credentials: default
    azure_subscription: default
```
