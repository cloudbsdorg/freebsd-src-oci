## 1. Purpose and product bar

### Goal

Ship **`ocifbsd`**: a **native FreeBSD** OCI runtime and container management stack, built on **jail(8), VNET, ZFS, RCTL, MAC/Capsicum, pf**, such that operators on FreeBSD **do not need Podman, Docker Engine, or a Linux userland** for day-to-day container lifecycle, images, networks, and (later) multi-node management.

### Product bar (“Podman irrelevant on FreeBSD”)

A FreeBSD operator can, **without Podman/Docker**:

| Capability | Operator experience | FreeBSD primitives |
|------------|--------------------|--------------------|
| Run a container from OCI bundle/image | `ocifbsd run` / create+start | jail, rootfs, hooks |
| Lifecycle | start/stop/kill/delete/state/list/inspect | jail_attach, signals, state dir |
| Images | pull/push/list/rmi, layer cache | ZFS datasets/snapshots/clones; OCI distribution |
| Networking | bridge/VNET, port publish | if_bridge, epair, VNET, pf |
| Resources | CPU/memory/pids | RCTL (+ process rlimits) |
| Compose-like stacks | convert + deploy simple multi-container | convert/ + orchestration (incremental) |
| Pods (lightweight) | shared net/volume group of jails | orchestration (after Phase 1 solid) |
| Observability | logs/events at least | logd/metrics (incremental) |
| Cluster (later) | multi-node schedule + trust | clustering + node auth (after single-node) |

Compatibility layer (Docker/Podman CLI familiarity) is **welcome** (see [002.0-CLI-Spec.md](./002.0-CLI-Spec.md)) but **secondary** to correct FreeBSD semantics. Never emulate Linux badly; map honestly or return clear errors.

### What this is *not*

- Not a Linux container runtime on FreeBSD via Linuxulator-as-primary-path  
- Not a Kubernetes replacement in v1 (orchestration is “K8s-like where useful,” simpler by default)  
- Not a license to rewrite FreeBSD base tooling (`jail`, `jexec`, `jls`, kernel jail code) without strong justification

## 2. FreeBSD-first rules (tread lightly)

This tree is **FreeBSD `src`**. CloudBSD hosts the fork for development; long-term intent is code that could be **proposed upstream** or shipped as a clean out-of-tree / ports-friendly component if base is not ready.

### Hard rules

1. **Prefer additive paths.** Primary home: `usr.sbin/ocifbsd/`, `tests/usr.sbin/ocifbsd/`. Wire via `usr.sbin/Makefile` only when build-ready and reviewed.
2. **Do not casually edit** `share/mk/`, `Makefile.inc1`, `sys/kern/kern_jail.c`, `usr.sbin/jail/`, or other core subsystems. If a change is truly required, isolate it, document *why*, and keep the patch minimal for FreeBSD review culture ([Contributing](https://docs.freebsd.org/en/articles/contributing/), style(9), man pages).
3. **Reuse existing FreeBSD infrastructure** before inventing:
   - Image build: `release/Makefile.oci`, `release/scripts/make-oci-image.sh` (already in base)
   - Tests: ATF + Kyua (`tests/…`)
   - Structured output: prefer **libxo(3)** over new JSON deps long-term (`json-c` is a pragmatic port dependency today; document migration)
4. **Coding style:** FreeBSD **style(9)** / KNF — not Linux kernel style, not “AI comment essay” style. No drive-by reformatting of unrelated files.
5. **Build system:** BSD make (`/usr/bin/make` on FreeBSD). On FreeBSD, do not require GNU make. Cross-build helpers for macOS are **opt-in** and must not redefine the primary FreeBSD-native path (see bootstrap lessons).
6. **Licensing:** Match FreeBSD norms (typically **BSD-2-Clause** for new usr.sbin code; preserve copyrights).
7. **Man pages and rc:** New user-facing tools need **section 8** (and 5 for config) when behavior stabilizes; rc.d only when install story is clear.
8. **Upstream politeness:** Large feature work stays on a feature branch until it builds cleanly, has tests, and is reviewable in sensible commits. No force-push to shared history without operator agreement.

### Guardrails from bootstrap (still valid)

- Do not treat “compiles” as “done.”  
- Do not trust “352 tasks complete” on `origin/devel`.  
- AI-generated scaffold is a **baseline to audit**, not gospel.

### Host hygiene (already applied on 001/003/005/006)

- Passwordless **doas** for `wheel` / `mlapointe` (mirrors sudo NOPASSWD)  
- Panic reboot: `debug.debugger_on_panic=0`, `kern.powercycle_on_panic=1`, `kern.sync_on_panic=0`  
- Boot env: `cloudbsd-YYYYMMDD` via **bectl**, activated and booted  

### Burst policy for 005 / 006

1. Prefer **parallel compile** (`make -j`) and **ATF/kyua** of `ocifbsd` / tests — high CPU, short duration.  
2. Do **not** reconfigure or destroy Bastille jails without explicit operator approval.  
3. Prefer a dedicated **work ZFS dataset** under `$HOME` or a disposable BE clone for experiments.  
4. If building inside Bastille `oci` on 006: confirm it is intended as a **dev** jail; FreeBSD version inside jail may lag host (observed 15.0-RELEASE userspace on CURRENT host kernel). Prefer **host** builds for CURRENT-matching binaries unless jail is updated.  
5. When hosts go offline, fall back to **001/003**.

## 7. Architecture (native, not Linux-shaped)

```
ocifbsd CLI / API
    │
    ├─ Runtime core (Phase 1) ── jailparam, lifecycle, state, hooks
    ├─ Image (Phase 2) ───────── ZFS store, pull/push, unpack
    ├─ Network (Phase 3) ─────── VNET/bridge/pf (+ CNI-compatible later)
    ├─ Security (Phase 4) ────── RCTL, MAC, Capsicum mapping
    └─ Management (Phase 5+) ─── rc, conf, release integration, docs
         │
         ├─ Orchestration (006) ─ pods/stacks after core is COMPLETED
         └─ Clustering (009) ──── multi-node after orchestration basics
```

**Design patterns (use professionally, FreeBSD-style):**

| Pattern | Where | Note |
|---------|-------|------|
| Clear module boundaries | SUBDIRs as libraries | Avoid circular deps; stubs only temporary |
| Template method | shared init/teardown for containers | One path for create→start→stop |
| Strategy | storage drivers (ZFS first) | Don’t abstract for fantasy backends |
| Builder | jailparam assembly from OCI spec | Testable pure-ish translation |
| TAOCP craft | O(n) string building, careful realloc | See LESSONS 2026-06-08 (Honcho / `.omo`) |

**Not:** heavyweight OO frameworks, Go-style microservices inside base usr.sbin, or Linux cgroup/seccomp APIs as first-class.

## 8. Quality engineering: red–green, coverage, craft

### Red–green–refactor (mandatory for code that claims COMPLETED)

1. **Red:** Write or enable an ATF test that fails for the intended behavior.  
2. **Green:** Minimal implementation to pass.  
3. **Refactor:** style(9), simplify, keep tests green.  

Never “fix the test to match buggy code.” (Honcho / operator standard.)

### Coverage targets

| Scope | Target | Notes |
|-------|--------|--------|
| **New or rewritten units** marked COMPLETED | **100% line coverage** of that unit’s `.c` under test | Prefer pure logic in testable compilation units |
| **Critical paths** (lifecycle, image unpack path selection, jailparam mapping) | **100%** of branches that are reachable without kernel | Kernel-touching paths: integration tests |
| **Legacy scaffold not yet rewritten** | No false COMPLETED; track SCAFFOLDED | Coverage theater on dead code is forbidden |

Measure with FreeBSD-appropriate tools when available (e.g. LLVM coverage in controlled builds); report in task notes. If tooling is missing, **exhaustive ATF case tables** are the interim contract.

### Test isolation (FreeBSD tradition)

| Level | Where | Rule |
|-------|-------|------|
| Unit | host userland | **No** experimental kernel modules on the developer laptop as host OS; mocks OK for jail/ZFS |
| Integration | freedev / bhyve VM / dedicated jail | Snapshot/BE rollback; never leave garbage jails |
| Performance / stress | isolated VM | Dedicated resources |

Output: **Kyua/ATF**, preferably machine-readable (TAP/JUnit where integrated).

### Performance discipline

- Prefer O(n) algorithms for string/layer assembly (Honcho: strcat-in-loop lesson)  
- Correct `realloc` usage (Honcho: realloc failure pattern)  
- LTO optional for size; not required for correctness

## 9. Phased roadmap to make Podman unnecessary

Statuses live in [005.0](./005.0-Risks-TODO.md). This section defines **acceptance**.

### Phase 0 — Lab & branch hygiene

- [ ] Merge `main` into `feature/oci-bootstrap` (no force-push)  
- [ ] fredev BE/doas/panic hygiene (001/003/005/006 done; 002 optional)  
- [ ] Document lab in Honcho  

### Phase 1 — Runtime core (blocks everything)

**Acceptance (all required):**

1. ATF unit tests for OCI→jailparam mapping (root, hostname, mounts metadata, freebsd.* extensions). ✅ (`oci2jail_test`)  
2. Integration tests on FreeBSD lab: create → start → state → kill → delete for a minimal FreeBSD rootfs/bundle. ✅ (`lifecycle_test` on fredev005)  
3. Unique jail name / persist behavior documented and tested. ✅  
4. Mount apply/unmount lifecycle tested (no leftover mounts). ✅ (`create_start_with_nullfs`)  
5. `ocifbsd.8` accurate for implemented commands. ✅ (updated 2026-07-22)  
6. **No** dependence on Podman for these flows. ✅  

**Code quality:** style(9); no stubs for claimed commands; red–green for each command.

**Still deferred inside Phase 1 (not blocking acceptance above):** hooks ATF, pause/resume real SIGSTOP tree, process.rlimits/RCTL, perf/stress harnesses (1.23–1.26).

### Phase 2 — Images

**Acceptance:** pull FreeBSD OCI image from a registry (or local layout); store on ZFS; run container from image; rmi GC path basic; tests for digest/path logic; integration pull if network policy allows (nexus on 006 may be useful as local registry later — **ask before** loading it).

### Phase 3 — Networking

**Acceptance:** VNET or shared-IP mode documented; bridge attach; at least one port-forward path via pf; tests for config generation; integration ping/TCP where isolation allows.

### Phase 4 — Resources / security

**Acceptance:** RCTL applied and cleaned; MAC/Capsicum mapping documented (honest gaps vs Linux seccomp); tests for rule build/cleanup.

### Phase 5 — Integration / polish

**Acceptance:** conf file + man; optional rc.d; `release/Makefile.oci` coexistence documented; OCI runtime-tools subset or documented gap list; README for FreeBSD operators.

### Management UX (overlaps 5 + 002)

Prioritize the **podman/docker mental model** only where it maps cleanly:

- `run`, `ps`, `rm`, `images`, `pull`, `network`, `volume` (volume may be ZFS dataset wrappers)  
- Reject or clearly unsupported: rootless user-ns Linux semantics, cgroup v2 paths, etc.

## 11. Task gates and definition of done

A task may move to **COMPLETED** only if:

1. FreeBSD style(9) respected; no unrelated drive-by edits  
2. Red–green tests added/updated and passing on **FreeBSD** (lab)  
3. Coverage bar for that unit met (§8)  
4. Man page / user-visible help updated if CLI changed  
5. Honcho lesson recorded if non-obvious  
6. [005.0](./005.0-Risks-TODO.md) status updated  
7. No silent stubs behind the feature flag or command  

**BUILDS** and **SCAFFOLDED** are honest intermediate states.
