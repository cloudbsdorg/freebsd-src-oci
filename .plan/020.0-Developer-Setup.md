> **Audience:** Developers working on `ocifbsd` from a macOS host. FreeBSD-native developers can skip the cross-build section but should still read the VM and CLion sections.

## 1. Prerequisites

| Tool | Version | Install | Purpose |
|------|---------|---------|---------|
| macOS | 14+ (Sonoma) or 15+ (Sequoia) | n/a | Host OS |
| Xcode Command Line Tools | latest | `xcode-select --install` | Provides `clang` baseline |
| Homebrew | latest | `brew install` from [brew.sh](https://brew.sh) | Package manager |
| Git | 2.40+ | `brew install git` | Source control |
| Python 3 | 3.11+ | preinstalled on macOS 14+ | Runs `tools/build/make.py` |
| `bmake` | 20240901+ | `brew install bmake` | FreeBSD make (not GNU make) |
| `llvm` | 18+ | `brew install llvm` | Provides `clang`, `lld`, `lldb` |
| FreeBSD VM | 14.x or 15.x | See [§ 7](#7-provision-a-freebsd-vm-for-testing) | Test target |
| UTM / QEMU / VirtualBox | latest | `brew install --cask utm` (or `qemu`, `virtualbox`) | VM host |
| CLion | 2026.1.2+ | JetBrains Toolbox or [jetbrains.com](https://jetbrains.com/clion) | IDE |

**Disk space:** ~25 GB for a full FreeBSD `buildworld`, ~2 GB for just the cross-compiled `ocifbsd` binary and tests.

**Time budget:** First-time setup takes 30–60 minutes. Subsequent rebuilds: 5–15 minutes (incremental).

## 2. Clone the Repository

```bash
# Fork on GitHub first: https://github.com/cloudbsdorg/freebsd-src-oci
git clone git@github.com:<your-username>/freebsd-src-oci.git
cd freebsd-src-oci

# Add the upstream FreeBSD OCI fork as a remote
git remote add upstream git@github.com:cloudbsdorg/freebsd-src-oci.git

# Fetch all branches and tags
git fetch --all --tags

# Check out the OCI bootstrap branch
git checkout feature/oci-bootstrap

# Verify the OCI source is present
ls usr.sbin/ocifbsd/  # Should show 18 subdirectories
```

**Branch state:** `feature/oci-bootstrap` tracks `origin/main` (the clean FreeBSD `main`), with the OCI source files brought in from `origin/devel` via `git checkout origin/devel -- <paths>`. See `.plan/005.0-Risks-TODO.md` § 0 for the full repository state.

## 3. Install `bmake` (FreeBSD make)

```bash
brew install bmake

# Verify
which bmake
# Expected: /opt/homebrew/bin/bmake (Apple Silicon) or /usr/local/bin/bmake (Intel)

bmake -f /dev/stdin <<'MAKEFILE'
all:
	@echo "bmake is working"
MAKEFILE
# Expected: bmake is working
```

**Why `bmake` and not GNU `make`?** FreeBSD's build system uses BSD make with `.if`/`.endif`/`.for`/`.endfor` directives and `${VAR}` substitution semantics that GNU make does not fully support. GNU make (at `/usr/bin/make` on macOS) will fail with cryptic errors on FreeBSD Makefiles.

**In CLion:** Always use the full path `/opt/homebrew/bin/bmake` (or `/usr/local/bin/bmake`) in Toolchain settings, not just `bmake`. CLion's PATH may not include Homebrew's bin directory.

## 4. Install LLVM Toolchain (`clang`, `lld`, `lldb`)

```bash
brew install llvm

# Add to ~/.zshrc (Apple Silicon)
export PATH="/opt/homebrew/opt/llvm/bin:$PATH"
export LDFLAGS="-L/opt/homebrew/opt/llvm/lib"
export CPPFLAGS="-I/opt/homebrew/opt/llvm/include"

# Reload shell
source ~/.zshrc

# Verify
which clang    # /opt/homebrew/opt/llvm/bin/clang
which lld      # /opt/homebrew/opt/llvm/bin/lld
which lldb     # /opt/homebrew/opt/llvm/bin/lldb
clang --version   # Should show clang 18+ (Homebrew LLVM)
lld --version     # Should show LLD 18+
lldb --version    # Should show lldb 18+
```

**Why LLVM, not Apple clang?** Apple clang (at `/usr/bin/clang`) is missing:
- `lld` (the cross-linker) — required by `tools/build/make.py` for FreeBSD userland
- `lldb` debugging of FreeBSD binaries
- Some cross-compilation flags (`--target=x86_64-unknown-freebsd`)

**Why `lld` is critical:** FreeBSD's build system since 14.x defaults to LLD as the linker. Without `lld`, the cross-build of userland libraries will fail at the linking stage with `ld: unknown option: --build-id` or similar.

**Verification:**
```bash
lld --version | head -1
# Expected: LLD 18.x.x ...
```

If you see `lld: command not found`, your `PATH` is not set correctly. Re-run `source ~/.zshrc`.

## 5. Cross-Build the FreeBSD Userland

> **Status (2026-09-01): best-effort, not a supported gate.** The macOS
> cross-build has to cross-compile the entire FreeBSD base-library set before it
> can build `ocifbsd` (effectively a partial `buildworld` from Darwin), and it
> depends on FreeBSD's own toolchain integration behaving on a non-FreeBSD host.
> In practice that is fragile: bmake's bootstrap self-tests can flake, and
> FreeBSD's prereq libraries (`libssp_nonshared`, `libgcc_eh`, compiler-rt) get
> compiled with the host Apple clang and Darwin headers, which reject FreeBSD
> source (e.g. `__hidden` from `<sys/cdefs.h>`). This is a limitation of
> cross-building FreeBSD from macOS, not of `ocifbsd`.
>
> **Supported route for a non-FreeBSD workstation:** build and test in a FreeBSD
> VM (see §6) or let CI do it (`.github/workflows/ocifbsd-freebsd-build.yml`
> spins up a FreeBSD VM and runs the full suite). `tools/cross-build/macos.sh`
> is kept as a best-effort helper — run it if you want to try the cross-build,
> but do not treat a clean `make cross-build` as a release requirement. The
> tier-1, authoritative build is always FreeBSD-native
> (`make -C usr.sbin/ocifbsd`).

The FreeBSD cross-build mechanism uses `tools/build/make.py` with `XCC`, `XLD`, `XAS`, `XDEV` environment variables. You only need the userland base libraries (`libc`, `libthr`, `libjail`, etc.) — a full `buildworld` is optional.

### 5.1. Set up the cross-build environment

Create `~/.freebsd-cross-build-env`:

```bash
# Apple Silicon (M1/M2/M3)
export XCC=/opt/homebrew/opt/llvm/bin/clang
export XCXX=/opt/homebrew/opt/llvm/bin/clang++
export XLD=/opt/homebrew/opt/llvm/bin/lld
export XAS=/opt/homebrew/opt/llvm/bin/clang
export XAR=/opt/homebrew/opt/llvm/bin/llvm-ar
export XNM=/opt/homebrew/opt/llvm/bin/llvm-nm
export XOBJCOPY=/opt/homebrew/opt/llvm/bin/llvm-objcopy
export XRANLIB=/opt/homebrew/opt/llvm/bin/llvm-ranlib
export XSTRINGS=/opt/homebrew/opt/llvm/bin/llvm-strings
export XSIZE=/opt/homebrew/opt/llvm/bin/llvm-size

# Target amd64 (FreeBSD x86_64)
export XDEV="amd64"
export TARGET="amd64"
export TARGET_ARCH="amd64"
```

Source it before any cross-build:
```bash
source ~/.freebsd-cross-build-env
```

### 5.2. Build the base libraries

```bash
cd /path/to/freebsd-src-oci

# Build base libraries (libc, libthr, libjail, etc.)
python3 tools/build/make.py TARGET=amd64 TARGET_ARCH=amd64 -j$(sysctl -n hw.ncpu) libraries

# This produces: obj/ (object files), obj.*/ (per-arch objects)
# Time: ~5–15 minutes on Apple Silicon, depending on parallelism
```

**Expected output:** `===> Building libraries for amd64` followed by per-library build lines. If you see `ld: command not found` or `lld: error: ...`, your `XLD` is not set correctly.

### 5.3. Optional: full `buildworld` (for full integration testing)

```bash
# Full buildworld — produces everything in the FreeBSD userland
# Time: ~30–90 minutes on Apple Silicon
python3 tools/build/make.py TARGET=amd64 TARGET_ARCH=amd64 -j$(sysctl -n hw.ncpu) buildworld

# Output: obj/ with all libraries, binaries, and the base system
```

You only need `buildworld` if you're testing integration with the full FreeBSD userland. For `ocifbsd`-only work, `libraries` is sufficient.

## 6. Build `ocifbsd` and Tests

```bash
# Build ocifbsd
cd /path/to/freebsd-src-oci
bmake -C usr.sbin/ocifbsd TARGET=amd64 TARGET_ARCH=amd64
# Output: usr.sbin/ocifbsd/ocifbsd

# Build tests
bmake -C tests/usr.sbin/ocifbsd TARGET=amd64 TARGET_ARCH=amd64
# Output: tests/usr.sbin/ocifbsd/ocifbsd_test

# Verify
file usr.sbin/ocifbsd/ocifbsd
# Expected: ELF 64-bit LSB executable, x86-64, ..., for FreeBSD
```

**Common error: `SRCS not found` or missing source files**

The `Makefile` in `usr.sbin/ocifbsd/` lists 96 source files. If you see errors about missing files like `api.c` or `cert.c`, you're missing the OCI source on your branch. Verify with:
```bash
ls usr.sbin/ocifbsd/api/api.c usr.sbin/ocifbsd/cert/cert.c
# Both should exist
```

If they're missing, you need to re-apply T2 (see `.omo/plans/oci-bootstrap.md`):
```bash
git checkout origin/devel -- usr.sbin/ocifbsd/
```

## 7. Provision a FreeBSD VM for Testing

Testing `ocifbsd` requires a real FreeBSD kernel (jail(8), VNET, ZFS). You cannot test on macOS.

### 7.1. Choose a VM technology

| VM | Pros | Cons | Setup |
|----|------|------|-------|
| **UTM** | Native Apple Silicon, GUI, simple | Limited snapshot scripting | [UTM guide](https://docs.getutm.app/) |
| **QEMU** | Cross-platform, full CLI, `qemu-img snapshot` | Slower on Apple Silicon (no HVF for FreeBSD) | `brew install qemu` |
| **VirtualBox** | Stable, `VBoxManage snapshot` | No native Apple Silicon (Rosetta only) | `brew install --cask virtualbox` |

**Recommended for Apple Silicon:** UTM for daily use, QEMU for scripted testing.

### 7.2. Provision the VM

Download FreeBSD 14.x or 15.x ISO from [freebsd.org/releases](https://www.freebsd.org/releases/).

**For UTM:**
1. Create a new VM → FreeBSD → 2 vCPU, 4 GB RAM, 20 GB disk
2. Install FreeBSD with ZFS, DHCP, sshd enabled
3. After install, install guest tools: `pkg install spice-vdagent`
4. Take a "clean" snapshot via File → Save Snapshot (named `clean`)

**For QEMU:**
```bash
qemu-img create -f qcow2 freebsd-oci.qcow2 20G
# Install FreeBSD via ISO (one-time)
qemu-system-x86_64 -m 4096 -smp 2 -hda freebsd-oci.qcow2 -cdrom FreeBSD-14.2-RELEASE-amd64-dvd1.iso -boot d
# After install, snapshot the clean state
qemu-img snapshot -c clean freebsd-oci.qcow2
# Restore to clean state (discards any test changes)
qemu-img snapshot -a clean freebsd-oci.qcow2
```

**For VirtualBox:**
```bash
VBoxManage createvm --name freebsd-oci --ostype FreeBSD_64 --register
VBoxManage modifyvm freebsd-oci --memory 4096 --cpus 2
VBoxManage createhd --filename freebsd-oci.vdi --size 20480
# Install via GUI
# After install, take a clean snapshot
VBoxManage snapshot freebsd-oci take clean
# Restore to clean state
VBoxManage snapshot freebsd-oci restore clean
```

### 7.3. Run `ocifbsd` tests in the VM

```bash
# From macOS, copy the binary and tests into the VM
scp usr.sbin/ocifbsd/ocifbsd freebsd-oci:/root/
scp tests/usr.sbin/ocifbsd/ocifbsd_test freebsd-oci:/root/

# SSH in
ssh freebsd-oci

# In the VM, enable jail features
sysrc jail_enable=YES
service jail start

# Run the tests
cd /root
./ocifbsd_test
```

**Test loop:**
1. Build on macOS
2. `scp` to VM
3. Run tests in VM
4. Restore VM to clean snapshot
5. Repeat

### 7.5. ATF test framework (kyua)

ocifbsd uses the **ATF** (Automated Testing Framework) via **kyua** (the FreeBSD test runner).

**In the VM, after deploying tests:**

```sh
ssh root@freebsd-oci
cd /root
kyua test -k tests/usr.sbin/ocifbsd/Kyuafile
```

**What kyua does:**
- Discovers all test programs in the Kyuafile
- Runs each test in an isolated jail (for ATF_REQUIRE_ROOT tests)
- Captures stdout/stderr/exit code
- Produces a `test-results.txt` report
- Supports parallel test execution: `kyua test -j 4`

**Common kyua commands:**
| Command | Purpose |
|---------|---------|
| `kyua test` | Run all tests |
| `kyua test -k <file>` | Run tests from a specific Kyuafile |
| `kyua test -v` | Verbose output |
| `kyua test -j N` | Parallel execution (N jobs) |
| `kyua report` | Show test results |
| `kyua report-html` | HTML report |

**CLion integration:** A "Run ocifbsd tests" run config is provided in `.idea/runConfigurations/Run_ocifbsd_tests.xml`. It wraps `ssh freebsd-oci 'cd /root && kyua test -k /root/tests/usr.sbin/ocifbsd/Kyuafile'` for one-click test execution from the IDE.

**See also:** `.plan/004.0-Testing.md` for the full test strategy.



Use the smoke test script at `.omo/drafts/vm-smoke-test.sh` (see T26 of the oci-bootstrap work plan).

## 8. Configure CLion 2026.1.2

CLion 2026.1.2 supports custom build targets and toolchains. The setup requires:

### 8.1. Toolchain (Settings → Build, Execution, Deployment → Toolchains)

Create a new toolchain named **`freebsd-bmake`**:

- **Name:** `freebsd-bmake`
- **Build system:** `Makefile`
- **Make:** `/opt/homebrew/bin/bmake` (full path, not just `bmake`)
- **Build tool:** `bmake`
- **C Compiler:** `/opt/homebrew/opt/llvm/bin/clang`
- **C++ Compiler:** `/opt/homebrew/opt/llvm/bin/clang++`
- **Debugger:** `/opt/homebrew/opt/llvm/bin/lldb`

### 8.2. Custom Build Targets

For `feature/oci-bootstrap`, add these Custom Build Targets (Settings → Build, Execution, Deployment → Custom Build Targets):

| Target Name | Command | Working dir |
|-------------|---------|-------------|
| `cross-build-libraries` | `python3 tools/build/make.py TARGET=amd64 TARGET_ARCH=amd64 -j$(sysctl -n hw.ncpu) libraries` | `$ProjectFileDir$` |
| `build-ocifbsd` | `/opt/homebrew/bin/bmake TARGET=amd64 TARGET_ARCH=amd64` | `$ProjectFileDir$/usr.sbin/ocifbsd` |
| `build-ocifbsd-tests` | `/opt/homebrew/bin/bmake TARGET=amd64 TARGET_ARCH=amd64` | `$ProjectFileDir$/tests/usr.sbin/ocifbsd` |
| `scp-ocifbsd-to-vm` | `scp usr.sbin/ocifbsd/ocifbsd freebsd-oci:/root/` | `$ProjectFileDir$` |
| `vm-snapshot-restore` | See VM-specific command in [§ 7](#7-provision-a-freebsd-vm-for-testing) | `$ProjectFileDir$` |

### 8.3. Run/Debug Configurations

Add these (Settings → Build, Execution, Deployment → Run/Debug Configurations):

- **`run-ocifbsd-via-ssh`**: SSH remote run on the FreeBSD VM
- **`debug-ocifbsd-via-ssh`**: SSH remote debug (lldb-remote)
- **`run-ocifbsd-test`**: Run `ocifbsd_test` in the VM via SSH
- **`make-cross-build`**: Custom build → `cross-build-libraries` + Build before launch
- **`restore-vm-snapshot`**: External tool → `vm-snapshot-restore`

### 8.4. Open the project

1. File → Open → select the `freebsd-src-oci` root
2. Trust the project
3. Wait for indexing (~5–10 minutes for 96 source files)
4. Right-click `usr.sbin/ocifbsd/Makefile` → "Load Makefile Project"
5. Run the `build-ocifbsd` custom build target to verify

## 9. Pitfalls and Gotchas

### 9.1. `bmake` vs GNU make

**Symptom:** `Makefile:42: Unassociated shell command "...command"...`

**Cause:** You're using GNU make (`/usr/bin/make`) instead of `bmake`.

**Fix:** Use `/opt/homebrew/bin/bmake` explicitly. In CLion Toolchain settings, set **Make** to the full path.

### 9.2. `lld: command not found`

**Symptom:** Cross-build fails with `lld: command not found` or `ld: unknown option: --build-id`.

**Cause:** Apple clang at `/usr/bin/clang` doesn't ship `lld`. You need Homebrew LLVM.

**Fix:**
```bash
brew install llvm
export PATH="/opt/homebrew/opt/llvm/bin:$PATH"
# Verify: which lld → /opt/homebrew/opt/llvm/bin/lld
```

### 9.3. Cross-build error: `SRCS not found`

**Symptom:** `bmake: don't know how to make api.c`

**Cause:** The OCI source files are missing from your branch. You're on `main` instead of `feature/oci-bootstrap`.

**Fix:**
```bash
git checkout feature/oci-bootstrap
# Or re-apply T2:
git checkout origin/devel -- usr.sbin/ocifbsd/
```

### 9.4. FreeBSD VM cannot reach the internet

**Symptom:** `pkg install` fails in the VM.

**Cause:** The VM's network interface is not configured for NAT or bridged mode.

**Fix:** In your VM settings, ensure the network adapter is set to:
- UTM: "Shared Network" (NAT) or "Bridged"
- QEMU: `-netdev user,id=net0 -device e1000,netdev=net0`
- VirtualBox: "NAT" or "Bridged Adapter"

### 9.5. CLion indexing hangs

**Symptom:** CLion stays at "Indexing..." for 30+ minutes.

**Cause:** The FreeBSD source tree has 80,000+ files; CLion indexes everything.

**Fix:** Right-click `usr.sbin/ocifbsd/` → "Mark Directory as" → "Project Sources and Headers". Then File → "Invalidate Caches" → "Just restart".

### 9.6. `git push` rejected (non-fast-forward)

**Symptom:** `git push origin feature/oci-bootstrap` fails.

**Cause:** Your local branch has diverged from `origin/feature/oci-bootstrap`.

**Fix:** Pull (rebase) first, then push:
```bash
git pull --rebase origin feature/oci-bootstrap
git push origin feature/oci-bootstrap
```

### 9.7. Snapshot restore doesn't undo file changes

**Symptom:** After `qemu-img snapshot -a clean`, the test binary is still the old one.

**Cause:** The snapshot only covers the VM disk image, not the host's `obj/` directory.

**Fix:** Rebuild on the host before re-running tests. The test loop is:
1. Edit code
2. `bmake` on host
3. `scp` to VM
4. Run test in VM
5. `qemu-img snapshot -a clean` (or equivalent)
6. Repeat
