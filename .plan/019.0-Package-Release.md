## 1. Overview

This document describes the release build process for the FreeBSD OCI container tooling project. The release tooling leverages FreeBSD's existing infrastructure in `release/` to produce:

- **ISO images** — Bootable installation media (disc1.iso, bootonly.iso, dvd1.iso)
- **Memory stick images** — USB installation images (memstick.img, mini-memstick.img)
- **FTP distribution sets** — Base system tarballs for network installation
- **Virtual machine images** — Pre-built VM images (VMDK, QCOW2, VHD, raw)
- **Cloud images** — Provider-specific images (EC2, GCE, Azure, OpenStack, Vagrant)
- **OCI container images** — OCI-compliant container base images

## 2. Release Build Prerequisites

### 2.1 Environment Requirements

| Requirement | Description |
|------------|-------------|
| **Native FreeBSD** | Release builds must run on FreeBSD (Linux compat mode insufficient) |
| **ZFS** | Recommended for storage efficiency with snapshots/clones |
| **sudo/su** | Root access required for chroot builds |
| **Disk Space** | 50GB+ recommended for full release build |
| **Memory** | 8GB+ recommended for parallel builds |

### 2.2 Required Components

- FreeBSD source tree (this repository)
- Ports tree (optional, for additional packages)
- Sufficient disk space in `/scratch` (default CHROOTDIR)

### 2.3 Key Scripts

| Script | Location | Purpose |
|--------|----------|---------|
| `release.sh` | `release/` | Main release build orchestration script |
| `make-oci-image.sh` | `release/scripts/` | Builds OCI-compliant container images |
| `mk-vmimage.sh` | `release/scripts/` | Creates VM disk images |
| `pkg-stage.sh` | `release/scripts/` | Stages packages for release |

## 3. Release Build Process

### 3.1 Quick Start

To build a complete release with all targets:

```bash
# Navigate to release directory
cd release

# Create custom release.conf
cat > release.conf << 'EOF'
#!/bin/sh
TARGET="amd64"
TARGET_ARCH="amd64"
KERNEL="GENERIC"
WITH_VMIMAGES="1"
WITH_CLOUDWARE="1"
WITH_OCIIMAGES="1"
CLOUDWARE="EC2 GCE VAGRANT-VIRTUALBOX"
WORLD_FLAGS="-j$(sysctl -n hw.ncpu)"
KERNEL_FLAGS="-j$(( $(sysctl -n hw.ncpu) / 2 ))"
EOF

# Build the release (requires root/sudo)
sudo sh release.sh -c release.conf
```

### 3.2 Step-by-Step Process

The `release.sh` script performs the following steps:

1. **Environment Setup** — Initialize build environment variables
2. **Chroot Preparation** — Create build chroot environment
3. **Build World** — Compile FreeBSD userland (`make buildworld`)
4. **Build Kernel** — Compile kernel(s) (`make buildkernel`)
5. **Install World** — Install to chroot (`make installworld`)
6. **Install Kernel** — Install kernel(s) to chroot
7. **Distribution** — Create distribution sets (`make distribution`)
8. **Package World** — Create distribution tarballs
9. **Build Media** — Create ISO/memstick images
10. **Build VM Images** — Create VM disk images (if enabled)
11. **Build Cloud Images** — Create cloud provider images (if enabled)
12. **Build OCI Images** — Create container base images (if enabled)

### 3.3 Chroot Build Environment

By default, releases are built in `/scratch` chroot:

```bash
# Default chroot directory
CHROOTDIR="/scratch"

# Build uses this structure:
/scratch/
├── cr/
│   └── (chroot environment)
└── release/
    └── (release artifacts)
```

## 4. Build Targets

### 4.1 Standard Targets (Makefile)

| Target | Output | Description |
|--------|--------|-------------|
| `cdrom` | disc1.iso | Full installation CD |
| `dvdrom` | dvd1.iso | Full installation DVD |
| `bootonly` | bootonly.iso | Boot-only CD (network install) |
| `memstick` | memstick.img | USB memory stick image |
| `mini-memstick` | mini-memstick.img | Minimal USB image |
| `ftp` | ftp/ | FTP distribution directory |
| `release` | All above | Build everything |
| `oci-release` | container-image-*.txz | OCI container images |

### 4.2 VM Targets (Makefile.vm)

| Target | Format | Description |
|--------|--------|-------------|
| `vm-release` | Various | All VM image formats |
| `vm-image-*.txz` | Raw | Base VM image packages |

### 4.3 Cloud Targets (Makefile.*)

| Makefile | Providers | Formats |
|----------|-----------|---------|
| `Makefile.ec2` | Amazon EC2 | AMI, VMDK |
| `Makefile.gce` | Google Cloud | GCE tarball |
| `Makefile.azure` | Microsoft Azure | VHD |
| `Makefile.vagrant` | Vagrant | Vagrant box |

### 4.4 OCI Image Targets

Six OCI image variants are built:

| Variant | Config | Description |
|---------|--------|-------------|
| `static` | `oci-image-static.conf` | Minimal static-linked base |
| `dynamic` | `oci-image-dynamic.conf` | Dynamic-linked base |
| `runtime` | `oci-image-runtime.conf` | Runtime environment |
| `notoolchain` | `oci-image-notoolchain.conf` | Without development tools |
| `toolchain` | `oci-image-toolchain.conf` | Full development environment |

## 5. Output Artifacts

### 5.1 Directory Structure

After a successful release build:

```
<release_dir>/
├── disc1.iso                 # Installation CD image
├── bootonly.iso              # Boot-only CD
├── memstick.img              # USB image
├── mini-memstick.img         # Minimal USB image
├── base.txz                  # Base system distribution
├── kernel.txz                # Kernel distribution
├── src.txz                   # Source code (if NOSRC not set)
├── ports.txz                 # Ports tree (if NOPORTS not set)
├── MANIFEST                  # Distribution manifest
│
├── vm/                       # VM images (if WITH_VMIMAGES)
│   ├── FreeBSD-*.vmdk
│   ├── FreeBSD-*.qcow2
│   └── FreeBSD-*.raw
│
├── cloud/                    # Cloud images (if WITH_CLOUDWARE)
│   ├── EC2/
│   ├── GCE/
│   └── Vagrant/
│
└── ociimages/                # OCI container images (if WITH_OCIIMAGES)
    ├── container-image-static.txz
    ├── container-image-dynamic.txz
    ├── container-image-runtime.txz
    ├── container-image-notoolchain.txz
    └── container-image-toolchain.txz
```

### 5.2 OCI Image Structure

Each OCI image tarball contains:

```
oci-layout                 # Image layout version file
index.json                # Image index
manifest.json             # Image manifest
config.json               # OCI runtime config
blobs/
└── sha256/               # Layer blobs (gzip compressed)
```

## 6. Configuration Options

### 6.1 Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `CHROOTDIR` | `/scratch` | Build chroot directory |
| `TARGET` | `${MACHINE}` | Target architecture (amd64, arm64, etc.) |
| `TARGET_ARCH` | `${MACHINE_ARCH}` | Target CPU architecture |
| `KERNEL` | `GENERIC` | Kernel configuration |
| `SRCBRANCH` | `main` | Source git branch |
| `WORLD_FLAGS` | `-j<ncpu>` | make buildworld flags |
| `KERNEL_FLAGS` | `-j<ncpu/2>` | make buildkernel flags |
| `MAKE_CONF` | `/dev/null` | Custom make.conf |
| `SRC_CONF` | `/dev/null` | Custom src.conf |

### 6.2 Feature Flags

| Flag | Description |
|------|-------------|
| `NOPORTS` | Skip ports tree in release |
| `NOSRC` | Skip source code in release |
| `NOPKGBASE` | Use traditional dist sets instead of pkgbase |
| `WITH_DVD` | Generate dvd1.iso |
| `WITH_COMPRESSED_IMAGES` | Compress images with xz |
| `WITH_VMIMAGES` | Build VM images |
| `WITH_COMPRESSED_VMIMAGES` | Compress VM images |
| `WITH_CLOUDWARE` | Build cloud provider images |
| `WITH_OCIIMAGES` | Build OCI container images |

### 6.3 OCI Image Configuration

Each OCI image variant has its own configuration file in `release/tools/`:

```bash
# Example: Build only specific OCI images
OCI_IMAGES="static dynamic"

# Or build all OCI images
WITH_OCIIMAGES="1"
```

## 7. Troubleshooting

### 7.1 Common Issues

| Issue | Solution |
|-------|----------|
| "git not found" | Install `devel/git` port/package |
| "Permission denied" | Run with sudo/su |
| "Out of disk space" | Increase `/scratch` size or use `OBJDIR` |
| "Chroot build failed" | Check kernel sources and build environment |

### 7.2 Build Logs

Logs are written to `/scratch/logs/` within the chroot environment:

```bash
ls /scratch/logs/
```
