## 15.1 Executive Summary

This document defines the REST/gRPC API specification for the `ocifbsdd` daemon. The API is the backbone of the entire system — the CLI, Web UI, and all external integrations communicate through it.

**Key Principles:**
- **Dual transport:** Unix socket for local, mTLS TCP for remote
- **Protobuf-first:** API defined in `.proto` files, JSON over HTTP for compatibility
- **Consistent errors:** Structured error responses with codes, messages, and details
- **Versioned:** `/v1/` prefix with backward compatibility guarantees
- **Authenticated:** Every request is authenticated (certs, tokens, or PAM)
- **Rate-limited:** Prevent abuse and accidental overload

**What This Document Covers:**
| Area | Problem | Our Approach |
|------|---------|------------|
| Transport | Docker uses Unix socket; Kubernetes uses HTTP | Support both: Unix socket locally, mTLS TCP remotely |
| Protocol | REST is verbose; gRPC requires HTTP/2 | Protobuf with JSON fallback; HTTP/2 where available |
| Auth | Multiple auth methods need unified handling | Middleware chain: cert → token → PAM → reject |
| Errors | Inconsistent error formats across endpoints | Standard `Error` message with code, message, details |
| Versioning | API changes break clients | `/v1/` prefix; deprecation headers; 6-month migration window |

## 15.2 API Design Principles

| Principle | Rationale |
|-----------|-----------|
| **Idempotency** | `POST /v1/containers` with same ID is idempotent; safe to retry |
| **Pagination** | All list endpoints use cursor-based pagination, not offset |
| **Filtering** | List endpoints support field selectors (`?fieldSelector=status=Running`) |
| **Streaming** | Log and event endpoints use server-sent events (SSE) or gRPC streams |
| **Consistency** | Same field names, types, and semantics across all endpoints |
| **Discoverability** | `GET /v1/` returns API documentation and endpoint list |

**Resource Naming:**
```
/v1/containers          # Collection
/v1/containers/{id}     # Individual resource
/v1/containers/{id}/logs # Sub-resource
```

**HTTP Methods:**
| Method | Usage |
|--------|-------|
| `GET` | Read resources |
| `POST` | Create resources |
| `PUT` | Full update (replace) |
| `PATCH` | Partial update |
| `DELETE` | Remove resources |

## 15.3 Transport and Protocol

### 15.3.1 Unix Domain Socket

Local communication uses a Unix domain socket:

```
Socket: /var/run/ocifbsd/api.sock
Permissions: root:ocifbsd 660
```

**Advantages:**
- No network overhead
- Kernel-enforced permissions
- No TLS required (but still authenticated)

**Usage:**
```bash
$ curl --unix-socket /var/run/ocifbsd/api.sock http://localhost/v1/containers
```

### 15.3.2 TCP with mTLS

Remote communication uses TCP with mandatory mTLS:

```
Port: 8443 (default, configurable)
Protocol: HTTP/2 over TLS 1.3
Client auth: Required (mutual TLS)
```

**Connection flow:**
```
Client                          Server
  │                               │
  ├── TLS handshake ─────────────>│
  │   (client presents cert)      │
  │                               │
  │<────────────── TLS handshake ─┤
  │   (server presents cert)        │
  │                               │
  ├── HTTP/2 request ────────────>│
  │   + Authorization header        │
  │                               │
  │<────────────── HTTP/2 response┤
```

### 15.3.3 Protocol Buffers

API defined in `api/ocifbsd/v1/ocifbsd.proto`:

```protobuf
syntax = "proto3";
package ocifbsd.v1;

service ContainerService {
  rpc CreateContainer(CreateContainerRequest) returns (Container);
  rpc StartContainer(StartContainerRequest) returns (Container);
  rpc StopContainer(StopContainerRequest) returns (Container);
  rpc DeleteContainer(DeleteContainerRequest) returns (Empty);
  rpc GetContainer(GetContainerRequest) returns (Container);
  rpc ListContainers(ListContainersRequest) returns (ListContainersResponse);
  rpc GetContainerLogs(GetContainerLogsRequest) returns (stream LogEntry);
}

message Container {
  string id = 1;
  string name = 2;
  string image = 3;
  string status = 4;
  map<string, string> labels = 5;
  int64 created_at = 6;
  int64 started_at = 7;
  ResourceSpec resources = 8;
  NetworkConfig network = 9;
}
```

**JSON mapping:**
| Protobuf | JSON | Example |
|----------|------|---------|
| `string` | string | `"hello"` |
| `int64` | number | `1714374720` |
| `bool` | boolean | `true` |
| `bytes` | base64 string | `"SGVsbG8="` |
| `map<K,V>` | object | `{"key": "value"}` |
| `repeated` | array | `["a", "b"]` |
| `Timestamp` | RFC 3339 string | `"2026-04-29T14:32:01Z"` |

## 15.4 Authentication

### 15.4.1 TLS Client Certificates

**Most secure option for automation and node-to-node communication.**

```bash
# Client presents certificate on every request
curl --cert client.crt --key client.key \
  https://manager-1:8443/v1/containers
```

**Certificate requirements:**
- Signed by cluster CA
- Not expired
- Not revoked (checked against CRL)
- Subject CN maps to RBAC identity

### 15.4.2 JWT Tokens

**For user sessions and service accounts.**

```bash
# Obtain token via login
curl -X POST https://manager-1:8443/v1/auth/login \
  -d '{"username":"alice","password":"secret"}'
# Response: {"token":"eyJhbGciOiJSUzI1NiIs..."}

# Use token in subsequent requests
curl -H "Authorization: Bearer eyJhbGciOiJSUzI1NiIs..." \
  https://manager-1:8443/v1/containers
```

**Token properties:**
- Signed with RS256 (RSA + SHA-256)
- Contains: `sub` (username), `roles`, `groups`, `exp`, `iat`
- Default lifetime: 24 hours
- Refreshable within 12 hours of expiry

### 15.4.3 PAM Authentication

**For interactive user sessions.**

```bash
# Login via PAM (returns JWT)
curl -X POST https://manager-1:8443/v1/auth/pam \
  -d '{"username":"alice","password":"secret"}'
```

**Auth middleware priority:**
1. TLS client cert presented → cert auth
2. `Authorization: Bearer <token>` → token auth
3. `Authorization: Basic <base64>` → PAM auth
4. Local Unix socket + UID 0 → bootstrap auth
5. None of the above → 401 Unauthorized

## 15.5 API Endpoints

### 15.5.1 Container Lifecycle

```
POST   /v1/containers              Create a container
GET    /v1/containers              List containers
GET    /v1/containers/{id}          Get container details
PUT    /v1/containers/{id}          Update container
DELETE /v1/containers/{id}          Delete container
POST   /v1/containers/{id}/start  Start container
POST   /v1/containers/{id}/stop     Stop container
POST   /v1/containers/{id}/kill     Kill container
POST   /v1/containers/{id}/pause    Pause container
POST   /v1/containers/{id}/resume   Resume container
GET    /v1/containers/{id}/logs     Get container logs (SSE stream)
GET    /v1/containers/{id}/exec     Exec into container (WebSocket)
```

**Example: Create container**
```bash
POST /v1/containers
Content-Type: application/json

{
  "name": "web-server",
  "image": "nginx:1.25",
  "command": ["nginx", "-g", "daemon off;"],
  "ports": [
    {"containerPort": 80, "hostPort": 8080}
  ],
  "resources": {
    "cpu": {"limit": 1.0, "request": 0.5},
    "memory": {"limit": "512Mi", "request": "256Mi"}
  },
  "labels": {
    "app": "web",
    "env": "production"
  }
}
```

**Response:**
```json
{
  "id": "abc123def456",
  "name": "web-server",
  "image": "nginx:1.25",
  "status": "created",
  "created_at": "2026-04-29T14:32:01Z"
}
```

## 15.6 Error Handling

All errors return a structured response:

```json
{
  "error": {
    "code": "CONTAINER_NOT_FOUND",
    "message": "Container 'web-server' not found",
    "details": {
      "container_id": "web-server",
      "suggestion": "Run 'ocifbsd container ls' to list available containers"
    },
    "request_id": "req-abc123",
    "timestamp": "2026-04-29T14:32:01Z"
  }
}
```

**HTTP Status Codes:**
| Status | Code | Meaning |
|--------|------|---------|
| 200 | OK | Success |
| 201 | Created | Resource created |
| 204 | No Content | Success, no body |
| 400 | Bad Request | Invalid request format |
| 401 | Unauthorized | Authentication required |
| 403 | Forbidden | Insufficient permissions |
| 404 | Not Found | Resource doesn't exist |
| 409 | Conflict | Resource already exists |
| 422 | Unprocessable | Valid request, invalid state |
| 429 | Too Many Requests | Rate limit exceeded |
| 500 | Internal Error | Server error |
| 503 | Service Unavailable | Temporarily unavailable |

**Error Codes:**
| Code | HTTP | Description |
|------|------|-------------|
| `CONTAINER_NOT_FOUND` | 404 | Container doesn't exist |
| `IMAGE_NOT_FOUND` | 404 | Image doesn't exist |
| `NETWORK_NOT_FOUND` | 404 | Network doesn't exist |
| `INVALID_SPEC` | 400 | Invalid container specification |
| `RESOURCE_EXHAUSTED` | 422 | Insufficient resources |
| `PERMISSION_DENIED` | 403 | RBAC denied access |
| `AUTH_REQUIRED` | 401 | No valid authentication |
| `RATE_LIMITED` | 429 | Too many requests |
| `INTERNAL_ERROR` | 500 | Unexpected server error |
| `NOT_IMPLEMENTED` | 501 | Feature not yet implemented |

## 15.7 Rate Limiting

Rate limits are applied per identity:

```yaml
# /etc/ocifbsd/ocifbsd.conf
api:
  rate_limiting:
    enabled: true
    # Per-identity limits (requests per minute)
    limits:
      default: 100
      authenticated: 1000
      service_account: 5000
      admin: 10000
    # Burst capacity (extra requests allowed)
    burst:
      default: 10
      authenticated: 100
      service_account: 500
      admin: 1000
    # Exempt endpoints
    exempt:
      - /v1/healthz
      - /v1/metrics
```

**Rate limit headers:**
```http
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 999
X-RateLimit-Reset: 1714374780
```

**When limit exceeded:**
```http
HTTP/1.1 429 Too Many Requests
Retry-After: 60
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 0
```

## 15.8 Versioning

**URL versioning:**
```
/v1/containers      # Current version
/v2/containers      # Future version (not yet)
```

**Backward compatibility guarantee:**
- Minor changes: Additive only (new fields, new endpoints)
- Major changes: `/v2/` prefix with 6-month deprecation window
- Deprecation headers:
  ```http
  Deprecation: true
  Sunset: Sat, 29 Oct 2026 00:00:00 GMT
  ```

**API discovery:**
```bash
GET /v1/
```

```json
{
  "version": "1.0.0",
  "endpoints": [
    {"path": "/v1/containers", "methods": ["GET", "POST"]},
    {"path": "/v1/images", "methods": ["GET", "POST", "DELETE"]},
    {"path": "/v1/networks", "methods": ["GET", "POST", "DELETE"]}
  ],
  "deprecated": [],
  "sunset": null
}
```
