### Status legend

| Status | Meaning |
|--------|---------|
| `NOT STARTED` | No meaningful source or verification for this task |
| `SCAFFOLDED` | Source exists (often AI-generated baseline); may have stubs; **not** production-ready |
| `BUILDS` | Compiles cleanly as part of the FreeBSD 16 native `make` tree |
| `TESTED` | Automated tests exist and pass for this slice of behavior |
| `COMPLETED` | Done for production use (implementation + tests + review) |
| `BLOCKED` | Cannot proceed without an external action (merge, host, tool) |

**Important:** `SCAFFOLDED` + `BUILDS` ≠ `COMPLETED`. Bootstrap completeness means *the tree compiles*, not that runtime behavior, OCI conformance, or production hardening are finished.

## 10. Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Jail parameter incompatibility | High | Extensive testing with all jail parameter combinations |
| ZFS dataset proliferation | Medium | Implement automatic cleanup, garbage collection |
| VNET performance overhead | Medium | Benchmark vs. shared IP; optimize if needed |
| Registry API changes | Low | Use stable OCI Distribution Spec v1.0 |
| Backward compatibility | Low | Existing jail workflows unchanged; new tooling is additive |
| Security model differences | Medium | Document FreeBSD MAC vs. Linux seccomp mapping |
| Rootless containers | Medium | Later phase: investigate unprivileged jail extensions |
| OCI spec compliance | High | Run OCI conformance tests, validate with `oci-runtime-tools` |
| AI-generated baseline quality | High | Bootstrap build gate + ATF; treat SCAFFOLDED code as audit surface, not finished product |
| Feature branch lag behind `freebsd:main` | High | Merge `main` into `feature/oci-bootstrap` before large refactors or PR |
| Overstated completion claims | High | Use legend above; only mark COMPLETED after tests + review |

## 13. Conclusion

The recommended approach remains building a native FreeBSD OCI runtime (`ocifbsd`) that:

- Uses jail, ZFS, VNET, RCTL, and MAC without Linux emulation
- Targets OCI Image and Runtime specifications
- Grows incrementally: **bootstrap → tested Phase 1 lifecycle → image/network → orchestration**

**As of 2026-07-21:** bootstrap (compile all modules) is done on `feature/oci-bootstrap`. The design docs (`.plan/`) remain the architecture source of truth. Task tracking must distinguish **scaffold/build** from **tested/complete**. The next critical path is **merging upstream `main` into the feature branch**, then hardening Phase 1 with real lifecycle tests—not expanding incomplete higher layers.
