# 13. PAM and System Credentials

**Author:** Mark LaPointe <mark@cloudbsd.org>
**Date:** 2026-04-29
**Repository:** https://github.com/cloudbsdorg/freebsd-src-oci
**Branch:** `oci-plan`

## 13.1 Executive Summary

This document defines how the cluster leverages FreeBSD's native **Pluggable Authentication Modules (PAM)** to allow users to authenticate using their existing system credentials. PAM integration is **optional but encouraged** — it enables organizations to use their existing identity infrastructure (local passwd, LDAP, Kerberos, Active Directory, YubiKey, etc.) without duplicating user databases or managing separate cluster passwords.

**Key Principles:**
- **Use what you already have** — if a user has a FreeBSD login, they have cluster access
- **PAM is optional** — clusters can run with token-only auth, cert-only auth, or PAM
- **No separate password database** — we do not maintain a shadow file for cluster users
- **System groups become RBAC roles** — `wheel` maps to `cluster-admin`, `staff` maps to `namespace-admin`
- **Common-sense defaults** — PAM auth works out of the box with standard FreeBSD installations

**What This Document Covers:**
| Area | Problem | Our Approach |
|------|---------|------------|
| User login | Kubernetes requires `kubectl` + tokens/certs | `ocifbsd login` uses PAM; same password as SSH |
| Group mapping | RBAC roles must be manually assigned | Auto-map system groups to cluster roles |
| Enterprise auth | LDAP/AD integration is complex | Use FreeBSD's existing PAM LDAP module |
| MFA | No built-in multi-factor auth | PAM supports YubiKey, TOTP, etc. via existing modules |

## 13.2 Why PAM

FreeBSD has a mature, well-documented PAM implementation in `libpam` and `pam.d`. Rather than reinventing authentication, we integrate with it:

| Benefit | Explanation |
|---------|-------------|
| **No new passwords** | Users authenticate with their existing system credentials |
| **Enterprise-ready** | LDAP, Kerberos, Active Directory, RADIUS — all via PAM modules |
| **MFA support** | YubiKey (`security/pam_yubico`), TOTP (`security/pam_oath`), etc. |
| **Centralized policy** | System administrators control auth policy in one place (`/etc/pam.d/`) |
| **Audit trail** | PAM modules log to syslog; cluster augments with API audit logs |
| **Familiar** | Every FreeBSD admin already knows how PAM works |

**Comparison:**
| Approach | Complexity | Maintenance | Enterprise Fit |
|----------|-----------|-------------|----------------|
| Kubernetes token auth | Medium | High (separate identity) | Poor |
| Kubernetes cert auth | High | High (CSR workflow) | Poor |
| Kubernetes OIDC | High | High (external IdP) | Medium |
| **Our PAM integration** | **Low** | **Low** | **Excellent** |

## 13.3 PAM Architecture

### 13.3.1 PAM Stack Design

The cluster daemon (`ocifbsdd`) links against `libpam` and calls `pam_authenticate()` when a user attempts to log in:

```
┌─────────────────────────────────────────┐
│           ocifbsd login                  │
│  ┌─────────────────────────────────┐   │
│  │  CLI prompts for username/pass  │   │
│  │  (or reads from stdin/script)   │   │
│  └─────────────────────────────────┘   │
│                   │                      │
│                   ▼                      │
│  ┌─────────────────────────────────┐   │
│  │  ocifbsdd API (local socket)    │   │
│  │  POST /v1/auth/login            │   │
│  │  { username, password }         │   │
│  └─────────────────────────────────┘   │
│                   │                      │
│                   ▼                      │
│  ┌─────────────────────────────────┐   │
│  │  PAM authenticate (libpam)        │   │
│  │  service: "ocifbsd"             │   │
│  │  stack: /etc/pam.d/ocifbsd      │   │
│  └─────────────────────────────────┘   │
│                   │                      │
│                   ▼                      │
│  ┌─────────────────────────────────┐   │
│  │  FreeBSD auth stack             │   │
│  │  (unix, ldap, kerberos, etc.)   │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

### 13.3.2 PAM Service Name

The cluster registers its own PAM service name: **`ocifbsd`**

**Default `/etc/pam.d/ocifbsd`:**
```
# PAM configuration for ocifbsd cluster authentication
# Installed automatically on first 'ocifbsd daemon init'

# Authentication
auth        required    pam_unix.so         no_warn try_first_pass
auth        optional    pam_ldap.so         no_warn try_first_pass
auth        optional    pam_krb5.so         no_warn try_first_pass

# Account management
account     required    pam_unix.so
account     optional    pam_ldap.so
account     optional    pam_krb5.so

# Session (not used for API auth, but defined for completeness)
session     required    pam_permit.so
```

**The installer creates this file if it does not exist.** Admins can customize it like any other PAM service.

### 13.3.3 PAM Conversation Function

For interactive logins, the CLI provides a PAM conversation function that prompts the user:

```
Interactive login:
  $ ocifbsd login
  Username: alice
  Password: ********
  Authenticated as alice (role: cluster-admin)
  Token saved to ~/.ocifbsd/token (expires: 2026-04-30 08:32 UTC)

Non-interactive login:
  $ echo 'password' | ocifbsd login --user alice --password-stdin
  Authenticated as alice (role: cluster-admin)
```

**PAM conversation messages are passed through to the user:**
- `PAM_PROMPT_ECHO_ON` → displayed as a prompt (e.g., "Username:")
- `PAM_PROMPT_ECHO_OFF` → displayed as a password prompt (hidden input)
- `PAM_ERROR_MSG` → displayed as an error
- `PAM_TEXT_INFO` → displayed as informational text

## 13.4 Authentication Flows

### 13.4.1 Interactive Login

```bash
$ ocifbsd login
Cluster: production (192.168.1.10)
Username: alice
Password: ********

Authenticated as alice
  Roles:   cluster-admin, namespace-admin
  Groups:  wheel, staff
  Token:   saved to ~/.ocifbsd/token
  Expires: 2026-04-30 08:32 UTC

$ ocifbsd pod ls
NAME    STATUS   IMAGE    NODE
web-1   Running  nginx    worker-1
web-2   Running  nginx    worker-2
```

### 13.4.2 Non-Interactive Login

For scripts, CI/CD, and automation:

```bash
# Read password from stdin
$ echo 'mypassword' | ocifbsd login --user alice --password-stdin

# Use a credentials file (chmod 600)
$ ocifbsd login --user alice --password-file /secure/alice.pw

# Kerberos ticket (no password needed)
$ kinit alice@EXAMPLE.COM
$ ocifbsd login --user alice --kerberos
Authenticated as alice via Kerberos ticket
```

### 13.4.3 API Token Generation

After PAM authentication succeeds, the API server generates a short-lived JWT:

```
PAM auth success
  │
  ▼
Lookup user in local user database (getpwnam)
  │
  ▼
Resolve system groups to RBAC roles
  │
  ▼
Generate JWT:
  {
    "sub": "alice",
    "uid": 1001,
    "groups": ["wheel", "staff"],
    "roles": ["cluster-admin", "namespace-admin"],
    "iat": 1714374720,
    "exp": 1714461120,
    "iss": "ocifbsd-cluster-production"
  }
  │
  ▼
Sign with cluster CA key
  │
  ▼
Return token to CLI → saved to ~/.ocifbsd/token
```

**Token properties:**
- Default lifetime: 24 hours
- Refreshed automatically on use (if within 12h of expiry)
- Revoked on `ocifbsd logout` or explicit revocation
- Contains no sensitive data (password never leaves PAM stack)

## 13.5 RBAC Integration

### 13.5.1 System Group to Role Mapping

By default, system groups map to cluster roles:

| System Group | Cluster Role | Permissions |
|--------------|--------------|-------------|
| `wheel` | `cluster-admin` | Full cluster access |
| `staff` | `namespace-admin` | Admin within assigned namespaces |
| `ocifbsd-operators` | `operator` | Read + restart pods, view logs |
| `ocifbsd-viewers` | `viewer` | Read-only access |

**This mapping is configurable:**
```yaml
# /etc/ocifbsd/ocifbsd.conf
auth:
  pam:
    enabled: true
    group_mapping:
      wheel: cluster-admin
      staff: namespace-admin
      operators: operator
      viewers: viewer
      # Custom groups
      db-admins: db-admin
      net-admins: network-admin
```

### 13.5.2 Default Role Assignment

If a user belongs to no mapped groups, they receive the `viewer` role by default (configurable):

```yaml
auth:
  pam:
    default_role: viewer   # viewer | none
```

Setting `default_role: none` means unmapped users cannot access the cluster at all.

### 13.5.3 Per-User Overrides

Administrators can override group-derived roles for specific users:

```bash
# Grant alice cluster-admin regardless of group membership
$ ocifbsd role bind cluster-admin --user alice --override

# Revoke bob's access even though he's in wheel
$ ocifbsd role bind none --user bob --override
```

Overrides are stored in the cluster state store and take precedence over group mapping.

## 13.6 CLI Commands

| Command | Description |
|---------|-------------|
| `ocifbsd login` | Interactive login via PAM |
| `ocifbsd login --user <name>` | Login as specific user |
| `ocifbsd login --password-stdin` | Read password from stdin |
| `ocifbsd login --password-file <path>` | Read password from file |
| `ocifbsd login --kerberos` | Use existing Kerberos ticket |
| `ocifbsd logout` | Revoke current token |
| `ocifbsd auth whoami` | Show current user and roles |
| `ocifbsd auth status` | Show auth method and token expiry |
| `ocifbsd auth refresh` | Refresh token before expiry |

**Examples:**
```bash
# Standard interactive login
$ ocifbsd login

# Login as root (uses PAM root auth)
$ ocifbsd login --user root

# Script-friendly login
$ echo "$PASSWORD" | ocifbsd login --user deploy --password-stdin

# Check who you are
$ ocifbsd auth whoami
User:     alice
UID:      1001
Groups:   wheel, staff
Roles:    cluster-admin, namespace-admin
Auth:     PAM (pam_unix)
Token:    valid until 2026-04-30 08:32 UTC
```

## 13.7 Configuration

### 13.7.1 PAM Policy File

The cluster installer creates `/etc/pam.d/ocifbsd` with sensible defaults. Admins customize it like any PAM service:

**Example: LDAP-only authentication:**
```
auth    required    pam_ldap.so
account required    pam_ldap.so
```

**Example: YubiKey + password:**
```
auth    required    pam_yubico.so id=1 key=/etc/yubikey_api_key
auth    required    pam_unix.so   try_first_pass
account required    pam_unix.so
```

**Example: Kerberos with fallback to local:**
```
auth    sufficient  pam_krb5.so
auth    required    pam_unix.so   try_first_pass
account sufficient  pam_krb5.so
account required    pam_unix.so
```

### 13.7.2 Cluster Auth Configuration

```yaml
# /etc/ocifbsd/ocifbsd.conf
auth:
  # Primary authentication method
  method: pam              # pam | token | cert | auto

  pam:
    enabled: true
    service_name: ocifbsd   # PAM service name
    group_mapping:
      wheel: cluster-admin
      staff: namespace-admin
      operators: operator
      viewers: viewer
    default_role: viewer
    token_lifetime: 24h
    token_refresh_window: 12h

  # Fallback if PAM is disabled or fails
  fallback:
    method: token           # token | cert | none
    allow_local_root: true  # Always allow root via local socket
```

**Auth method priority (`auto`):**
1. If client presents valid TLS client cert → cert auth
2. If client presents valid token → token auth
3. If PAM is enabled and credentials provided → PAM auth
4. If local socket and UID 0 → allow (for bootstrap)

## 13.8 Security Considerations

| Concern | Mitigation |
|---------|-----------|
| Password transmitted to API | Only over local Unix socket or mTLS; never in plaintext over network |
| Brute force | Rate limiting: 5 attempts per minute per IP, 10 per user |
| Token theft | Short-lived (24h); auto-refresh requires re-auth after max lifetime |
| PAM module compromise | PAM runs as unprivileged `ocifbsd` user; cannot access cluster CA |
| Group membership changes | Token includes group snapshot at login time; re-login required for updates |
| Root always has access | Configurable: `fallback.allow_local_root: false` disables this |

**Audit logging:**
Every PAM authentication attempt is logged:
```json
{
  "timestamp": "2026-04-29T08:32:00Z",
  "event": "auth.pam",
  "user": "alice",
  "source_ip": "192.168.1.45",
  "result": "success",
  "pam_service": "ocifbsd",
  "groups": ["wheel", "staff"],
  "roles": ["cluster-admin", "namespace-admin"]
}
```

## 13.10 Future Enhancements

- **Smart card authentication:** PAM module for PKCS#11 smart cards (CAC/PIV)
- **Biometric authentication:** PAM module for fingerprint readers (`security/pam_fprint`)
- **Time-based restrictions:** PAM `time` module for business-hours-only access
- **Geographic restrictions:** PAM module for IP-based location validation
- **Session recording:** Integrate with `security/ttyrec` for privileged session recording
- **SSO via SAML/OIDC:** Optional PAM module for cloud identity providers
