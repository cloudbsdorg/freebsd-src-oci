## 10.1 Executive Summary

This document defines the security model for the FreeBSD native container orchestration system. Security is not an afterthought — it is woven into every layer from node bootstrapping to secret injection.

**Key Principles:**
- **Zero trust by default** — every request is authenticated and authorized
- **Secrets are first-class** — not environment variables, but encrypted, auditable, rotatable assets
- **Credentials never touch disk in plaintext** — memory-only where possible, encrypted at rest otherwise
- **The web UI is just another pod** — it runs with the same RBAC restrictions as any other workload
- **Audit everything** — who did what, when, and whether it succeeded

## 10.2 Security Architecture

### 10.2.1 Defense in Depth

```
┌─────────────────────────────────────────────────────────────┐
│                    Perimeter (pf/iptables)                   │
│  ┌─────────────────────────────────────────────────────┐    │
│  │              TLS (mTLS between pods)                 │    │
│  │  ┌─────────────────────────────────────────────┐    │    │
│  │  │           RBAC (API authorization)           │    │    │
│  │  │  ┌─────────────────────────────────────┐    │    │    │
│  │  │  │      MAC labels (jail isolation)     │    │    │    │
│  │  │  │  ┌─────────────────────────────┐    │    │    │    │
│  │  │  │  │   RCTL (resource limits)    │    │    │    │    │
│  │  │  │  │  ┌─────────────────────┐   │    │    │    │    │
│  │  │  │  │  │  Secret injection    │   │    │    │    │    │
│  │  │  │  │  │  (tmpfs, read-only)  │   │    │    │    │    │
│  │  │  │  │  └─────────────────────┘   │    │    │    │    │
│  │  │  │  └─────────────────────────────┘    │    │    │    │
│  │  │  └─────────────────────────────────────┘    │    │    │
│  │  └─────────────────────────────────────────────┘    │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

### 10.2.2 Threat Model

| Threat | Mitigation |
|--------|-----------|
| Compromised node | Node identity via TLS; compromised node cannot impersonate others |
| Compromised pod | MAC labels + RCTL limit blast radius; secrets not visible to other pods |
| Man-in-the-middle | mTLS on all cluster communication; certificate pinning |
| Privilege escalation | `allow_privileged: false` by default; MAC prevents jail escapes |
| Secret exfiltration | Secrets in tmpfs (memory-only); never written to disk; audit all access |
| Replay attacks | All API requests include timestamps + nonces; replay window < 60s |
| Insider threat | RBAC limits scope; audit logs immutable and forwarded off-host |

## 10.3 Role-Based Access Control (RBAC)

### 10.3.1 Roles and Permissions

Roles define what actions can be performed on which resources:

```yaml
role: cluster-admin
rules:
  - resources: ["*"]
    verbs: ["*"]
    namespaces: ["*"]

---
role: namespace-admin
rules:
  - resources: ["stacks", "pods", "services", "networks", "volumes", "secrets"]
    verbs: ["create", "read", "update", "delete", "list"]
    namespaces: ["self"]   # Only own namespace

---
role: developer
rules:
  - resources: ["stacks", "pods", "services"]
    verbs: ["create", "read", "update", "list"]
    namespaces: ["self"]
  - resources: ["secrets"]
    verbs: ["read", "list"]   # Cannot create/modify secrets
    namespaces: ["self"]

---
role: observer
rules:
  - resources: ["*"]
    verbs: ["read", "list"]
    namespaces: ["*"]

---
role: service-account
rules:
  - resources: ["services", "endpoints"]
    verbs: ["read", "list"]
    namespaces: ["self"]
```

**Resource Types:** `nodes`, `namespaces`, `stacks`, `pods`, `services`, `networks`, `volumes`, `secrets`, `images`, `cluster`

**Verbs:** `create`, `read`, `update`, `delete`, `list`, `watch`, `exec`, `logs`, `migrate`, `drain`

### 10.3.2 Role Binding

Bind roles to users or service accounts:

```yaml
# Bind user 'alice' to namespace-admin in production
binding:
  user: alice
  role: namespace-admin
  namespace: production

# Bind service account 'api-service' to service-account in production
binding:
  service_account: api-service
  role: service-account
  namespace: production
```

### 10.3.3 RBAC CLI

```bash
# Create a role
ocifbsd role create developer --rules stacks,pods,services:create,read,update,list

# Bind a role to a user
ocifbsd role bind developer --user alice --namespace production

# List roles
ocifbsd role ls

# Check permissions (can Alice delete pods in production?)
ocifbsd auth can-i delete pod --user alice --namespace production
# Output: no

# Show effective permissions for a user
ocifbsd auth whoami --user alice
```

## 10.4 Credential Management

### 10.4.1 Node Identity

Every node in the cluster has a unique identity:

- **Bootstrap:** Node generates a key pair on first boot
- **Enrollment:** CSR submitted to cluster CA; certificate issued with node role
- **Rotation:** Certificates auto-rotate before expiry (default 90-day lifetime)
- **Revocation:** Compromised nodes added to CRL; cluster rejects their connections

```
Node Boot ──► Generate Key Pair ──► CSR to CA ──► Certificate ──► Join Cluster
                                                    (90 days)
                                                       │
                                              Auto-rotate at 80%
```

### 10.4.2 User Authentication

Users authenticate to the cluster API via:

| Method | Use Case | Implementation |
|--------|----------|---------------|
| **TLS client cert** | Automation, CI/CD | x509 with cluster CA |
| **Token** | Interactive CLI, web UI | Short-lived JWT (24h default) |
| **Kerberos/GSSAPI** | Enterprise integration | FreeBSD Heimdal |
| **LDAP/AD** | Corporate environments | Optional LDAP connector |

**Token Lifecycle:**
```bash
# Login (interactive)
ocifbsd login --user alice
# Enter password:
# Token saved to ~/.ocifbsd/token (expires: 2026-04-30 02:39 UTC)

# Use token for API calls
curl -H "Authorization: Bearer <token>" https://cluster.local/v1/pods

# Logout (revoke token)
ocifbsd logout
```

### 10.4.3 Service Accounts

Service accounts are identities for pods:

```yaml
service_account: api-service
namespace: production

# Automatically mounted into pods at:
# /var/run/ocifbsd/serviceaccount/token
# /var/run/ocifbsd/serviceaccount/ca.crt
# /var/run/ocifbsd/serviceaccount/namespace
```

Pods use these credentials to talk to the cluster API:
```bash
# Inside a pod — automatically authenticated
curl https://cluster.local/v1/services
# Uses mounted token; no manual auth required
```

## 10.5 Secret Management

### 10.5.1 Secret Types

| Type | Use Case | Example |
|------|----------|---------|
| **generic** | Arbitrary key-value data | API keys, passwords |
| **tls** | TLS certificate + key | HTTPS termination |
| **registry** | Container registry credentials | Docker Hub login |
| **ssh** | SSH private keys | Git clone, rsync |
| **env** | Environment-specific values | Database URLs |

### 10.5.2 Secret Storage

Secrets are encrypted at rest and in transit:

```
┌─────────────────────────────────────────┐
│           Secret Storage                 │
│  ┌─────────────────────────────────┐    │
│  │  Encryption Layer (AES-256-GCM)│    │
│  │  ┌─────────────────────────┐    │    │
│  │  │  ZFS Dataset (encrypted) │    │    │
│  │  │  zroot/ocifbsd/secrets   │    │    │
│  │  │  ┌─────────────────┐    │    │    │
│  │  │  │  Secret Record   │    │    │    │
│  │  │  │  {name, data,    │    │    │    │
│  │  │  │   metadata}      │    │    │    │
│  │  │  └─────────────────┘    │    │    │
│  │  └─────────────────────────┘    │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

**Storage Properties:**
- **At rest:** AES-256-GCM encryption on ZFS dataset
- **In transit:** mTLS between nodes
- **In memory:** Mounted as tmpfs (never touches disk unencrypted)
- **Backup:** Encrypted snapshots; decryption key stored separately

### 10.5.3 Secret Rotation

Secrets can be rotated automatically or on-demand:

```yaml
secret:
  name: db-password
  type: generic
  rotation:
    enabled: true
    interval: 30d        # Rotate every 30 days
    grace_period: 7d   # Old value valid for 7 days after rotation
    notify:
      - service: api     # Notify these services to reload
      - service: worker
```

**Rotation Process:**
1. Generate new secret value
2. Update secret record (versioned)
3. Notify subscribed services
4. Services reload credentials (SIGHUP or exec)
5. After grace period, old version purged

### 10.5.4 Secret CLI

```bash
# Create a secret from literal value
ocifbsd secret create db-password --type generic \
  --from-literal password=supersecret123 \
  --namespace production

# Create a secret from file
ocifbsd secret create tls-cert --type tls \
  --from-file cert.pem --from-file key.pem \
  --namespace production

# List secrets
ocifbsd secret ls --namespace production

# Inspect secret (shows metadata only, not values)
ocifbsd secret inspect db-password --namespace production

# Rotate a secret
ocifbsd secret rotate db-password --namespace production

# Delete a secret
ocifbsd secret rm db-password --namespace production
```

## 10.6 Web UI

### 10.6.1 Architecture

The web UI is a containerized application running on the cluster — not a separate daemon:

```
┌─────────────────────────────────────────┐
│           Cluster Manager 1              │
│  ┌─────────────────────────────────┐   │
│  │  Pod: ocifbsd-webui             │   │
│  │  ┌─────────────────────────┐    │   │
│  │  │  Web UI Container        │    │   │
│  │  │  (nginx + React app)     │    │   │
│  │  │  Port: 8443              │    │   │
│  │  │  RBAC: webui-role        │    │   │
│  │  └─────────────────────────┘    │   │
│  └─────────────────────────────────┘   │
│              │                         │
│              ▼                         │
│  ┌─────────────────────────────────┐   │
│  │  Service: ocifbsd-webui         │   │
│  │  Ingress: https://cluster.local │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

**Deployment:**
```yaml
stack: ocifbsd-webui
namespace: system
pods:
  webui:
    replicas: 2
    image: ocifbsd/webui:latest
    ports:
      - target: 8443
        publish: 8443
    resources:
      memory: 256M
      cpus: 0.5
    service_account: webui-service
```

### 10.6.2 RBAC Integration

The web UI operates under a restricted service account:

```yaml
role: webui-role
rules:
  - resources: ["stacks", "pods", "services", "networks", "volumes"]
    verbs: ["read", "list", "watch"]
    namespaces: ["*"]
  - resources: ["stacks", "pods", "services"]
    verbs: ["create", "update", "delete"]
    namespaces: ["self"]
  - resources: ["nodes"]
    verbs: ["read", "list"]
    namespaces: ["*"]
  - resources: ["secrets"]
    verbs: ["read", "list"]
    namespaces: ["self"]
    # Secrets are masked in UI; values never displayed
```

**UI Behavior:**
- Users log in via the web UI (token-based auth)
- UI proxies all requests to cluster API using user's credentials
- Users can only see/modify resources their role permits
- Secret values are never displayed; only metadata (name, type, rotation date)
- All UI actions are logged to audit trail

### 10.6.3 Communication Channel

The web UI communicates with the cluster API through a dedicated, authenticated channel:

```
Browser ──► HTTPS ──► Ingress ──► Web UI Pod
                          │
                          ▼
                    ┌─────────────┐
                    │  API Proxy   │
                    │  (in-pod)    │
                    │  mTLS to     │
                    │  cluster API  │
                    └─────────────┘
                          │
                          ▼
                    Cluster API (mTLS)
```

**Security Properties:**
- Browser → UI: TLS 1.3 with valid cluster certificate
- UI → API: mTLS with service account credentials
- API validates user's token on every request
- Web UI pod cannot bypass RBAC — it is subject to the same authorization as any client

## 10.7 TLS and Encryption

### 10.7.1 In-Transit Encryption

All cluster communication is encrypted:

| Channel | Encryption | Authentication |
|---------|-----------|----------------|
| Node ↔ Node | mTLS (TLS 1.3) | x509 mutual auth |
| Client ↔ API | TLS 1.3 | Token or client cert |
| Pod ↔ Pod | mTLS (optional) | Service account certs |
| Registry pull | TLS 1.3 | Registry credentials |

**Certificate Hierarchy:**
```
Cluster CA (root)
  ├── Manager certs (server + client)
  ├── Worker certs (client only)
  ├── API server cert (server)
  ├── Service account certs (per-namespace)
  └── Web UI cert (server)
```

### 10.7.2 At-Rest Encryption

| Data | Encryption Method |
|------|-------------------|
| Secrets | AES-256-GCM on ZFS dataset |
| State store | Raft log encryption (AES-256-GCM) |
| Images | ZFS native encryption (optional) |
| Backups | GPG-encrypted before export |

## 10.8 Audit Logging

Every security-relevant event is logged:

| Event | Logged Data | Retention |
|-------|-------------|-----------|
| API request | User, action, resource, result, timestamp | 90 days |
| Authentication | Success/failure, method, source IP | 1 year |
| Secret access | User/pod, secret name, action | 1 year |
| RBAC change | Who changed what role/binding | 1 year |
| Node join/leave | Node ID, certificate, timestamp | 90 days |
| Privileged operation | Exec into pod, host access | 1 year |

**Audit Log Format:**
```json
{
  "timestamp": "2026-04-29T02:39:00Z",
  "event": "secret.access",
  "user": "alice",
  "namespace": "production",
  "resource": "secret/db-password",
  "action": "read",
  "result": "allow",
  "source_ip": "10.0.1.45",
  "user_agent": "ocifbsd-cli/1.0"
}
```

**Forwarding:**
- Audit logs forwarded to syslog and optional remote SIEM
- Local logs append-only (chflags append)
- Remote forwarding via TLS-encrypted syslog

## 10.10 Future Enhancements

- **Hardware security modules (HSM):** Store cluster CA key in an external HSM
- **FIPS 140-2 compliance:** Use only FIPS-validated cryptographic modules
- **Multi-factor authentication:** TOTP/WebAuthn for interactive logins
- **Policy as code:** Open Policy Agent (OPA) integration for advanced authorization
- **Runtime security:** Falco-like behavioral monitoring for anomalous pod activity
- **Vault integration:** HashiCorp Vault as external secret backend
