## 1. LTO (Link-Time Optimization) works natively on FreeBSD 16

**Verified:** Add `-flto` to **both** CFLAGS and LDFLAGS. The base
linker (`/usr/bin/ld.lld`, the LLVM linker) supports it natively —
no ports, no special tools.

**Impact on ocifbsd main binary:** 50712 → 45112 bytes (**-11%**,
-5600 bytes), with zero source changes. Shared libraries also
shrank 0.1-0.3%.

**Why both flags?** `-flto` in CFLAGS tells the compiler to emit
LLVM bitcode instead of object code (with `-fno-lto` available to
opt out per-file). `-flto` in LDFLAGS tells the linker to do the
cross-TU optimization pass. Missing either and LTO is a silent
no-op.

**Don't use for:** build servers where compile time matters more
than output size (LTO adds ~10-30% to link time).

## 2. `if (ptr != NULL)` after `realloc()` is a latent NULL-deref

**The bug pattern:**
```c
ptr = realloc(ptr, new_size);
if (ptr != NULL) {
    // use ptr
}
```

**Why it fails:** `realloc()` on failure returns NULL **and leaves
the old pointer valid**. The check `if (ptr != NULL)` is true
(the old pointer is still there), so the code happily writes into
a buffer that's too small. Classic silent buffer overflow.

**The correct pattern:**
```c
new_ptr = realloc(ptr, new_size);
if (new_ptr == NULL) {
    free(ptr);          /* or just don't free — old ptr is still valid */
    return ERROR;
}
ptr = new_ptr;
```

**Found in:** `convert/k8s.c` during the strcat optimization pass.
Fixed in the same commit (`271f8e5730c`).

## 3. `strcat()` in a loop is O(n²) — always track length + use `memcpy`

**Why:** `strcat(dest, src)` walks `dest` to find the NUL before
appending. If you `strcat` inside a loop, you pay O(n) per call,
O(n²) total.

**The pattern:**
```c
/* BAD: O(n²) total */
for (i = 0; i < n; i++) {
    strcat(result, items[i]);
}

/* GOOD: O(n) total */
size_t len = 0;
for (i = 0; i < n; i++) {
    size_t ilen = strlen(items[i]);
    memcpy(result + len, items[i], ilen);
    len += ilen;
    result[len] = '\0';
}
```

**Found and fixed in 4 sites** in one pass:
- `convert/k8s.c` (k8s doc merge loop)
- `image/zfs_store.c` (zfs command output capture — was calling
  `strlen(result)` per line!)
- `network/network.c` (command string builder — `cmd_len` was
  already tracked, just wasn't being used)
- `cert/cert.c` (final `"]"` append — one-time but still O(n))

## 4. `scp` tarball path gotcha — `--strip-components` counts levels, not prefixes

**The failure mode:**
```sh
# On local:
tar czf opt.tgz usr.sbin/ocifbsd/Makefile usr.sbin/ocifbsd/foo.c
# Tarball contains: usr.sbin/ocifbsd/Makefile, usr.sbin/ocifbsd/foo.c

# On VM:
tar xzf opt.tgz --strip-components=1
# Result: ocifbsd/Makefile, ocifbsd/foo.c  ← WRONG
# Should be: usr.sbin/ocifbsd/Makefile, usr.sbin/ocifbsd/foo.c
```

`--strip-components=1` strips the first path level (`usr.sbin`),
leaving `ocifbsd/...` which creates a `~/ocifbsd-build/ocifbsd/`
directory that nothing references.

**The fix:** create the tarball from inside the target directory
so paths are relative:
```sh
cd usr.sbin/ocifbsd
tar czf opt.tgz Makefile foo.c
# Tarball contains: Makefile, foo.c

# On VM, cd into the target first:
cd ~/ocifbsd-build/usr.sbin/ocifbsd
tar xzf opt.tgz
# Result: Makefile, foo.c  ← CORRECT
```

No `--strip-components` needed.

## 5. VM recovery when `git pull` is blocked — `git reset --hard`

**The failure mode:** VM's working tree has uncommitted build
artifacts (`.o` files, `ocifbsd` binary, `._*` macOS metadata,
etc.). `git pull` says "cannot pull with rebase: You have unstaged
changes." `git stash` saves the changes but the pull still fails
because of untracked files.

**The fix (fast):**
```sh
ssh vm
cd ~/ocifbsd-build
git fetch origin feature/oci-bootstrap
git status -sb                          # confirm `[behind N]`
git reset --hard origin/feature/oci-bootstrap
# Wipes working tree AND index. Untracked files survive.
# Then re-apply any local changes manually.
```

**Why this beats `git stash` + `git pull --rebase`:** the stash
dance is fragile when untracked files exist (they're not stashed
by default, the rebase refuses to start). The hard reset is
atomic and explicit.

**Always check first:**
```sh
git status -sb
# Look for: `## branch...origin/branch [behind N]`
# If behind, the reset will fast-forward you to origin HEAD.
```

## 6. FreeBSD 16 build system patterns (consolidated)

These are the FreeBSD 16 quirks that came up repeatedly during
the ocifbsd bootstrap. Each one cost a build cycle to discover.

| Pattern | What it means | Example |
|---------|---------------|---------|
| `LIBADD+= name` | Base-system library (in `src.libnames.mk`) | `LIBADD+= jail` |
| `LDADD+= -lname` | Port library (not in base) | `LDADD+= -lcurl` |
| `CFLAGS+= -I/usr/local/include` | Port headers (curl, json-c live at `/usr/local`) | `CFLAGS+= -I/usr/local/include/json-c` |
| `LDFLAGS+= -L/usr/local/lib` | Port library path | `LDFLAGS+= -L/usr/local/lib` |
| `<sys/json.h>` | **REMOVED** in FreeBSD 16 — use json-c port | `#include <json-c/json.h>` |
| `<sys/sha.h>` | **DOES NOT EXIST** — use `<sha256.h>` from libmd | `#include <sha256.h>` |
| `SHA256_*` symbols | **MOVED** from libc to libmd in 16 | `LIBADD+= md` |
| `mkdirp()` | **NOT EXPORTED** from libutil — copy locally per-file | local helper, 4 lines |
| `hmac_sha256()` | **NOT IN** libmd — wrap OpenSSL `HMAC()` | 6-param wrapper |
| `<base64.h>` | **DOES NOT EXIST** — implement from scratch or use openssl | 30-line impl |
| `<uuid.h>` | FreeBSD style, NOT `<uuid/uuid.h>` (that's Linux) | `#include <uuid.h>` |
| `<netinet6/in6.h>` | Has `#error "do not include"` — use `<netinet/in.h>` | use `<netinet/in.h>` |
| `<pam/pam_appl.h>` | Linux path — use `<security/pam_appl.h>` on FreeBSD | `<security/pam_appl.h>` |
| `archive_read_support_format_tar_grzip` | **REMOVED** from libarchive | just delete the call |
| `archive_entry_stat` | Takes 1 arg in libarchive, not 2 | `archive_entry_stat(entry)` |
| `archive` library | Base-system — use `LIBADD+= archive`, NOT `LDADD+=-larchive` | `LIBADD+= archive` |

**Why `LIBADD` vs `LDADD` matters:** FreeBSD's `bsd.libnames.mk`
validates `LIBADD` names against the base system. `LDADD` is
for explicit `-lfoo` flags (typically ports). Putting `-larchive`
in `LDADD` triggers the error "These libraries should be
LIBADD+=foo rather than DPADD/LDADD+=-lfoo" and the build dies.

## 7. Session-level observations

**What worked well:**
- LTO is the single highest-impact build flag (11% main binary
  reduction for free).
- The strcat→memcpy pass also fixed a latent NULL-deref — code
  quality optimization that found a real bug.
- Using `ld.lld` (already in base) avoided any port installs.

**What was harder than expected:**
- The VM's stale working tree blocked `git pull` twice in one
  session. The hard-reset recovery is now in the lessons.
- The `tar xzf --strip-components` gotcha cost an iteration.
- The `CONVERT_ERROR` vs `CONVERT_MEMORY_ERROR` enum name mismatch
  (I used the wrong one first) only surfaced at compile time,
  not at the call site.

**What I'd do differently:**
- Always `git status -sb` on the VM before any push/pull dance.
- Always create tarballs from inside the target directory.
- When the strcat→memcpy pattern is needed, check for the
  realloc NULL-deref in the same pass.
